# Оновлення EmpirecraftFeudal до 1.4.0

Це серверний плагін для чинної збірки Minecraft 1.20.1 / Mohist 71a84ff7 / Towny 0.101.2.0. Towny у цій збірці потребує Java 21. Сам Feudal компілюється з Java 17 bytecode. Клієнтам та ADM нічого додавати не потрібно.

## Установлення на наявний сервер

1. Повністю зупиніть сервер. Збережіть резервну копію `plugins/EmpirecraftFeudal/`, даних Towny та світів. Папка плагіна містить чинну БД, а не тільки налаштування.
2. Приберіть старий `empirecraft-feudal-1.3.0.jar` (або `1.2.0`) та інші старі JAR саме цього плагіна з `plugins/`. Залиште єдиний `empirecraft-feudal-1.4.0.jar` із цього архіву. Контрольна сума лежить поруч.
3. **Збережіть наявні `plugins/EmpirecraftFeudal/feudal.mv.db` і `config.yml`.** Не копіюйте тестові БД і не замінюйте папку даних. Архів містить лише новий JAR та довідкові файли.
4. За потреби додайте лише розділ `politics:` із `reference-configs/config.yml` до наявної конфігурації. Параметри торгівлі, династій, договорів та валют зберігаються. Без ручного доповнення нові параметри мають значення з комплектної конфігурації плагіна.
5. Видайте незалежним будівельним перевіряльникам `empirecraft.feudal.castle.review`. За замовчуванням він доступний OP. Правитель, навіть OP, не може схвалити власний замок або установи.
6. Запустіть сервер повністю, без `/reload`. Під час першого запуску до створення політичних таблиць зберігається узгоджена H2-копія `backups/before-politics-1.4-<час>.zip`. Якщо копіювання або запуск не вдаються, плагін вимикається з помилкою в консолі.
7. Перевірте `/plugins`, `/t state status`, `/t fief info`, `/wallet`, `/currency list` та сценарії в `VALIDATION.md` на копії сервера.

## Як мігрують чинні володіння

Наявні баронства, графства, герцогства й королівства зберігають початкові статуси. Це сумісність з версією 1.2.0, а не ретроспективна перевірка всіх замків сервера. **Нові** зареєстровані після оновлення володіння починають політичний розвиток із поселення.

Чинні UUID, скарбниці, гроші, валюти, золоті рахунки, данина, васальні договори, борги, торговельні замовлення та журнали предметних передач залишаються у своїх таблицях. Політичні таблиці додаються до тієї самої БД. Підвищення статусу не змінює мерів, королів, Towny-привати або власників чужих вотчин.

Налаштування популяції та строків — стартовий баланс із документа. Наприклад, для імперії типово потрібно 50 активних мешканців. Для невеликого сервера ці числа можна змінити в `politics.population` і `politics.requirements`, після чого перезапустити сервер.

## Відновлення та відкат

При невизначеній виборній передачі подивіться рядок `political_elections` зі статусом `PREPARED` і фактичного правителя Towny. `/t state election resume ID` продовжує її зі сторони колишнього правителя, переможця або адміністратора. Якщо новий правитель уже встановлений, синхронізація завершує журнал без повторної зміни влади. Адміністратор може виконати `/t state election abort ID` лише якщо у Towny досі старий правитель. Це не скасовує вже виконані вибори.

Для повернення до старого плагіна зупиніть сервер і відновіть узгоджені резервні копії **і БД Feudal, і даних Towny**. Просте встановлення старого JAR не відкочує вибори, політичне об’єднання чи рух грошей.

## Межі встановлення

У цьому середовищі виконано компіляцію проти точних Spigot/Towny API і тести на справжній H2. Живий Mohist із робочими світами й кількома гравцями не запускався. До такої перевірки оновлення слід розглядати як кандидат для тестового сервера.

## Сумісність з поточною збіркою

Feudal 1.4.0 включає як політику PR #13, так і чинну провізію з PR #20. Однаковий старий номер 1.3.0 більше не означає взаємозамінні збірки. Залишайте рівно один Feudal JAR — 1.4.0.

Провізія, `/t provision`, її сезонні коефіцієнти, облік простою та поріг розпаду 96 реальних годин збережені. Для неї на сервері залишається потрібним Calendar 1.1.0; календарний JAR цим політичним оновленням не замінюється. Якщо ця версія календаря вже встановлена, клієнтів оновлювати не потрібно.

Поточний `config.yml` зберігається. Комплектні значення `politics:` та `provisions:` читаються як defaults; ручне перенесення потрібне тільки для власних відмінних налаштувань. База `feudal.mv.db`, Towny, світи та ADM не перезаписуються пакетом. Якщо старий PR #13 уже запускався локально, збережені політичні записи також використовуються без скидання.

Зниклі через голод володіння виключаються з чинної адміністрації/ради, а історія, скарбниці й прийняті борги залишаються. За зникнення об’єднавчого центру вцілілі фізичні провінції отримують назад політичну автономію; кошти не розподіляються автоматично. Архівний союзний борг може сплатити останній власник відповідної скарбниці або адміністратор.

Після зняття ділянки особистої вотчини замок потребує нового огляду й незалежного підтвердження; старе підтвердження не дозволяє підвищити статус на вже втраченій землі. Автоматична зміна столиці Towny при підтвердженому голодному розпаді має вузький системний виняток; звичайні виборні обмеження збережені.
