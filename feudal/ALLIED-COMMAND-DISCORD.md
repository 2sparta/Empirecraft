# Союзні командири, заявки кораблів та серверний Discord-бот

Версії оновлення: Feudal 1.17.0, Towny Recruits 1.5.0 та Engagement 1.1.0.
Обидва моди встановлюються однаковими JAR на сервер і всіх клієнтів.
Плагін Feudal встановлюється тільки на сервер. Перед заміною зупиніть
сервер і збережіть світ та дані `plugins/EmpirecraftFeudal/`.

## Призначення союзників

Мер або адмірал призначає капітана через `/fleet`. Капітан може бути
мешканцем міста-власника чи союзного міста. Війна має перевагу над союзом.
Після розриву союзу право керування відкликається, а призначення очищується.
Адмірал, як і раніше, є посадою власного міста.

Для полків використовуються наявні команди:

```
/nation regiment leader <полк> <гравець>
/nation regiment commander <полк> <загін> <гравець>
/nation regiment form <полк> <назва_загону> <гравець>
```

Правитель чи уповноважений офіцер нації-власника може призначити жителя
союзного міста, зокрема іншої союзної нації. Призначений командир бачить
свій полк у списку та може керувати ним; посада в його власній державі
не дає прав на інші чужі полки. За однакових назв використовуйте UUID полку.

Це делегування командування: місто-власник, нація, військовий ліміт та
громадянство гравця зберігаються. Права захисту рекрутів визначаються за
містом-власником полку. Перепризначення діє і на вивантажених солдатів.
Після розриву союзу командування повертається представнику власного міста
під час наступної синхронізації Towny.

Продаж полку також дозволяє вибрати союзного командира покупця.
Найм на окрему битву з тимчасовим громадянством зберігає окремі правила:
перед наймом командир і бійці мають належати місту-продавцю. Захист
командира найманців та блокування зміни складу чинного договору діють.

## Обов’язкова заявка на корабель

1. Гравець будує корпус без фізики, наводиться на його блок у межах 8 блоків
   і вводить `/shiprequest submit Назва корабля`. Назву також можна вписати
   у формі «Подати заявку» в `/fleet`. Клік VS-паличкою чи пляшкою Sails
   звичайного гравця відкриває цю форму.
2. Заявка з назвою, містом заявника й точними координатами надходить
   адміністрації в Discord. `/shiprequest list` показує власні заявки;
   `/shiprequest withdraw <ID>` відкликає ще не зібрану заявку.
3. Адміністратор оглядає корпус і виконує `/shipadmin approve <ID>` або
   `/shipadmin reject <ID> <причина>`. Саме схвалення ще не надає фізику.
4. Адміністратор використовує VS-паличку на **тому самому блоці**, координати
   якого вказані в заявці. Перевірка працює для VS Ship Assembler,
   VS Ship Creator та пляшки Sails. Без схваленої заявки збирання блокується.
   Пляшка Sails додатково зберігає стандартну перевірку прав Towny на
   знищення блоків корпусу.
5. Після створення фізичного корабля автоматично відкривається меню
   міста-власника та назви. Назва й місто заявника вже заповнені; адміністратор
   може їх змінити, переглянути й підтвердити. До підтвердження корабель
   утримується на місці, керування та бій для нього заблоковані.

Адміністративний дозвіл `empirecraft.feudal.ships.admin` типово належить
операторам і консолі. Команди:

```
/shipadmin list
/shipadmin approve <ID заявки> [примітка]
/shipadmin reject <ID заявки> [причина]
/shipadmin finish <ID заявки>
/shipadmin owner <ID корабля> <місто>
```

`finish` повторно відкриває меню вже зібраного корабля, якщо його закрили
або адміністратор вийшов. `owner` працює й для раніше зареєстрованих кораблів;
старий `/fleet assign <ID корабля> <місто>` залишається адміністративним
скороченням. Зміна власника очищує попередні призначення екіпажу та капітана,
скасовує продаж і повертає резерв аукціону за чинними правилами флоту.
Заявки й незавершене оформлення зберігаються після перезапуску.

Заявник має належати до активного міста. Дозволено до трьох незавершених
заявок на гравця й одну нову заявку за хвилину. Інструменти збирання
не створюють окремий корабель із блока вже фізичного корпусу. Звичайне
обслуговування оформленого корабля використовує наявні права екіпажу.

## Бот на тому самому сервері

Бот працює всередині Feudal у JVM Minecraft. Окремі Node.js, Python,
контейнер чи зовнішній хостинг для нього не потрібні. Мережеве надсилання
працює в окремому потоці; читання Towny та бази залишається в серверному.

Повідомлення містять назву, заявника, місто, координати або світ та команду
перегляду у грі. Події:

- `/t castle inspect` — заявка на незалежний огляд нової версії замку;
- `/market submit` — заявка на реєстрацію базару;
- `/shiprequest submit` або форма `/fleet` — заявка на створення корабля
  з назвою, координатами та командами схвалення чи відмови.

Розгляд усіх заявок виконується командами Minecraft.
Бот не змінює рішення через Discord. Повторний огляд тієї самої споруди
не створює дублікати. Перший запуск також підхоплює наявні нерозглянуті
заявки замків і базарів.

1. Створіть застосунок і Bot у [Discord Developer Portal](https://discord.com/developers/applications).
2. Запросіть його на свій Discord-сервер із правами **View Channel**,
   **Send Messages** та **Embed Links**. Привілейовані Gateway Intents не потрібні.
3. Дозвольте боту доступ до приватного текстового каналу адміністрації.
   У режимі розробника Discord скопіюйте ID цього каналу.
4. Передайте токен у змінну середовища процесу Minecraft
   `EMPIRECRAFT_DISCORD_BOT_TOKEN`, а ID каналу — у
   `EMPIRECRAFT_DISCORD_ADMIN_CHANNEL_ID`.

Приклад назв змінних є в `server/discord-bot.env.example`. Скопіюйте його
в локальний `discord-bot.env`, заповніть і завантажте оточення в службу
запуску Minecraft. Для systemd можна використати `EnvironmentFile=`.
Обмежте доступ до файла власником сервера. Токен не додавайте до Git,
`config.yml`, повідомлень чи скриншотів. Після зміни токена потрібен
перезапуск процесу Minecraft.

У `plugins/EmpirecraftFeudal/config.yml` увімкніть:

```yaml
discord:
  notifications:
    enabled: true
    token-env: EMPIRECRAFT_DISCORD_BOT_TOKEN
    channel-id: '' # Порожньо: береться EMPIRECRAFT_DISCORD_ADMIN_CHANNEL_ID.
    channels:
      castles: ''
      markets: ''
      ships: ''
```

Для окремих каналів заповніть їхні ID в лапках у `channels`. Порожній
канал використовує спільний `channel-id` або змінну середовища.

Адміністративні команди з дозволом `empirecraft.feudal.discord`
(типово оператор або консоль):

```
/feudaldiscord status
/feudaldiscord reload
/feudaldiscord retry
```

`status` показує наявність токена, маршрути й стан черги без самого токена.
`reload` перечитує конфігурацію. `retry` повторює відкладені повідомлення
після виправлення прав або каналу; ліміт Discord продовжує враховуватися.

Без токена, під час збою мережі чи вимкненого бота повідомлення залишаються
в таблиці `registration_outbox` бази Feudal. Після перезапуску надсилання
відновлюється. HTTP 429 враховує `Retry-After`; мережеві та серверні помилки
використовують затримку повтору. Стабільний nonce зменшує повтори після
невизначеного результату HTTP; абсолютної гарантії одного повідомлення
після довгого аварійного простою Discord не надає.

Бот використовує REST API лише для сповіщень, тому його статус у списку
учасників Discord може залишатися «офлайн». Назви та описи гравців не
можуть викликати згадки користувачів, ролей або `@everyone`.

Протокол: [Discord Create Message](https://discord.com/developers/docs/resources/message#create-message)
та [Rate Limits](https://discord.com/developers/docs/topics/rate-limits).
