# Виправлення заснування міста — 27.10.2026

При `/t new Назва` Towny вже додає першу ділянку до майбутнього міста, перш
ніж плагін перевіряє провізію. Перевірка очікувала нуль ділянок і відхиляла
заснування. Внести їжу було неможливо, оскільки гравець ще не був жителем.

Тепер дозволено саме першу домашню ділянку незавершеного нового міста.
Після завершення Towny створюється облік фактичної території, а гравець
відкриває `/t provision` і вносить їжу. Для наступних приватів залишається
вимога запасу на наступні 24 реальні години. Зміна домашньої ділянки,
аванпости, захоплення й масовий приват не дають безкоштовного розширення.
Без чинного сигналу календаря перевірка, як і раніше, блокує операцію.

## Встановлення

Це серверне виправлення поточного `EmpirecraftFeudal 1.4.1` зі збереженням
назви файла та сумісності бази. Зупиніть сервер, замініть
`plugins/empirecraft-feudal-1.4.1.jar` файлом із цього пакета й запустіть
сервер. У ZIP є відповідна SHA-256. Клієнтську збірку оновлювати не потрібно.
Чинні `plugins/EmpirecraftFeudal/config.yml` та `feudal.mv.db` залишаються
на сервері; пакет їх не містить.

## Перевірки

`python3 feudal/build.py` компілює плагін із `--release 17` та запускає
наявні тести фінансів, політики, провізії й торгівлі.
`python3 provisions/test.py` перевіряє конфігурацію та комплектність плагіна.
`python3 provisions/test_claims.py` на Java 21 перевіряє справжні класи
Towny 0.101.2.0: початкову ділянку до призначення мера, відсутність
передчасного запису в H2, завершення заснування, внесення їжі, розширення
та резервування масового привату. Окремо перевіряються відсутність обходу
через home-block, аванпост, захоплення, нульову/подвійну територію та
відсутній календар. Java 21 потрібна тестам, які завантажують внутрішні
класи планувальника цієї версії Towny.

Тестове оточення використовує мінімальний Bukkit Server proxy і відтворює
проміжний стан Towny на справжніх об'єктах; повний Mohist-сервер і GUI в
клієнті не запускалися.
