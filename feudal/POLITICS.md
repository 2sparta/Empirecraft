# Політична система EmpirecraftFeudal 1.4.0

## Модель

У держави є чотири незалежні характеристики: статус розвитку, форма правління, територіальний устрій і міжнародні союзи. Наприклад, королівство може мати абсолютну монархію, пряму адміністрацію та персональну унію.

Власна вотчина — зареєстровані міста, якими правитель реально керує у Towny. Прямі провінції зберігаються окремо після погодженого договору. Політична територія охоплює власну вотчину, прямих та непрямих васалів і погоджені адміністративні регіони. Популяція рахується за унікальними UUID активних жителів цих міст, без подвійного підрахунку. Типове вікно активності — 30 діб.

Васальні переходи використовують чинні договори `/t vassal`: підписи сторін, попереднього сюзерена, строки, данину та перевірку циклів. Для вимог розвитку враховуються тільки прямі васали потрібного **політичного** статусу з чинним договором. Просте членство міста у Towny-нації не замінює підписаного васалітету. Кілька паперових регіонів з тією самою вотчиною не збільшують кількість васальних володінь. Для заснування графства дозволені договори між баронствами однакового статусу; сам договір не видає графський титул. Цикли перевіряються також між васальними й адміністративними зв’язками.

## Гілки розвитку

| Гілка | Переходи |
|---|---|
| Феодальна | SETTLEMENT → BARONY → COUNTY → DUCHY → KINGDOM → EMPIRE |
| Особливе заснування | Незалежне COUNTY + 3 прямі BARONY → KINGDOM, без DUCHY |
| Осіла племінна | SETTLEMENT → TRIBE → PRINCIPALITY → KINGDOM |
| Військово-племінна | TRIBE → HORDE → KHANATE → KHAGANATE |
| Централізована | SETTLEMENT → CENTRAL_STATE → CENTRAL_KINGDOM → CENTRAL_EMPIRE |
| Торговельна | SETTLEMENT → FREE_CITY → TRADE_REPUBLIC; кілька держав утворюють TRADE_LEAGUE |

Султанат і військовий орден — форми правління, а не примусові наступні рівні. Абсолютизм також є окремою формою правління. Імперська влада не переписує васальні вотчини у власність імператора.

Числа, населення, строки та будівельні вимоги змінюються у `politics:`. Типово діють: баронство — 5 активних жителів і замок; графство — 2 прямі барони; герцогство — 2 графства або 4 баронства; особливе королівство — 3 прямі барони; імперія — 3 підлеглі королівства й 50 жителів. Централізована держава потребує 3 прямо керованих поселень; каганат — 3 ханств і 40 жителів.

Казна, резиденція, адміністрація, податкова система, рада, ринок, військовий устав та інші інституції підтверджуються незалежним перевіряльником із приміткою. Плагін **не видає існування цих установ за повністю автоматично розпізнаний факт**. Перелік ознак: `residence`, `administration`, `treasury`, `tax`, `laws`, `officials`, `council`, `market`, `assembly`, `tribute`, `military`.

## Основний порядок

Замість `n:ID` і `t:ID` можна використовувати однозначні назви володінь, `держава:Назва` або `місто:Назва`. Команда `/t state status` без аргументу обирає старше володіння гравця. Для двох держав з одним правителем краще вказувати ID явно.

```text
/t state status [володіння]
/t state charter ВОЛОДІННЯ Текст письмового статуту...
/t state decision ID_РІШЕННЯ
/t state vote ID_РІШЕННЯ yes
/t state capital ВОЛОДІННЯ МІСТО
/t state progress ВОЛОДІННЯ kingdom
/t state advance preview ВОЛОДІННЯ kingdom
/t state advance submit ВОЛОДІННЯ kingdom
/t state advance confirm ВОЛОДІННЯ
/t state history ВОЛОДІННЯ
```

Закони, столиця й устрій спочатку створюються як проєкти рішень. Монарх підтверджує власний проєкт окремим голосом. У республіці потрібні дві третини зафіксованого електорату. Показати проєкт можна через `decision`; для монархічних проєктів також потрібне явне підтвердження голосом.

Вимоги переходу мають спостерігатися як виконані протягом 7 реальних діб. Відлік зберігається в БД. Втрата спостережуваних умов або зміна структури/правителя скидає готовність; `confirm` перевіряє їх повторно. Це періодична перевірка даних, а не доказ безперервного існування кожного блока у вивантаженому чанку. Вже отриманий статус не понижується автоматично. Втрата населення або власної вотчини фіксується як попередження з налаштовуваним пільговим строком; журнал повідомляє про його завершення й відновлення умов. Санкції залишаються рішенням адміністрації.

## Замок

```text
/t castle pos1 ВОЛОДІННЯ
/t castle pos2 ВОЛОДІННЯ
/t castle inspect ВОЛОДІННЯ
/t castle status ВОЛОДІННЯ
/t castle review ВОЛОДІННЯ 2 Башта та функціональне приміщення підтверджені
/t castle history ВОЛОДІННЯ
```

Гравець стоїть на висоті підлоги й позначає два протилежні **внутрішні** кути прямокутного двору. Огляд рахує корисну площу з підлогою та вільним простором над нею, перевіряє кам’яний периметр зовні двору, висоту стін і оформлений прохід із дверима або хвірткою. Типові межі — 144 блоки двору, 4 блоки стіни, максимум 64 × 64. Для неправильної форми потрібен прямокутний основний двір; довільні багатокутники не трасуються.

Чотири автоматичні критерії обов’язкові. Перевіряльник оцінює ще 0–4 пункти: головна будівля, приміщення, стиль і завершеність. Разом потрібно 6/8. Зміна геометрії або правителя скидає ручне схвалення. Уся споруда має лежати в особистій вотчині. Огляд читає тільки завантажені чанки й не змінює блоки. Для відкритих перевірок баронства за синхронізацію повторно оглядається обмежена кількість замків; перед підтвердженням виконується новий огляд.

## Вотчини та пряма адміністрація

```text
/t fief info ВОЛОДІННЯ
/t fief vassals ВОЛОДІННЯ
/t fief liege ВОЛОДІННЯ
/t fief tree ВОЛОДІННЯ
/t fief contract ВОЛОДІННЯ
/t state certify ВОЛОДІННЯ administration yes Перевірено адміністративну резиденцію
/t state province propose ЦЕНТР ПРОВІНЦІЯ BASE 1.00 Узгоджені повноваження губернатора...
/t state province sign ID_ПЛАНУ
/t state adminvote ДЕРЖАВА ID_ПЛАНУ
/t state releasevote ЦЕНТР ПРОВІНЦІЯ
```

Центр і чинний власник провінції особисто підписують план із компетенціями, валютою та податком. Для республіканської сторони рада має попередньо схвалити саме цей план через `adminvote` і `/t state vote`. Чинний васальний договір спершу погоджено завершується; його не замінюють адміністративним приєднанням без згоди.

Губернатор залишається місцевим правителем Towny. Запис компетенцій не дає безумовного доступу до чужих приватів, скринь або скарбниць. Податок — погоджений щоденний переказ між звичайними рахунками; за нестачі коштів фіксується попередження. Золотий резерв не використовується. Утримання центральної адміністрації типово коштує 1 BASE за провінцію на добу. Воно не стягується повторно в тому самому періоді. Після тривалої зупинки немає необмеженого нарахування пропущених діб. Нестача коштів дає попередження з пільговим періодом; автоматичних повстань чи конфіскацій немає.

Централізація: до 75 балів за частку прямо керованих зареєстрованих міст і до 25 за п’ять інституцій. Площа приватів не додає балів. Для абсолютизму потрібні 75 балів, не менше 60% прямого управління, потрібні інституції й строк стабільності. Після голосування перехід завершується `/t state execute ID_РІШЕННЯ`.

## Вибори й бюджети

```text
/t state government ВОЛОДІННЯ republic
/t state budget ВОЛОДІННЯ p:UUID BASE 10.00
/t state vote ID_РІШЕННЯ yes
/t state election open ВОЛОДІННЯ
/t state election candidate ID_ВИБОРІВ
/t state election vote ID_ВИБОРІВ ІМ’Я_КАНДИДАТА
/t state election close ID_ВИБОРІВ
```

Типовий строк посади — 30 діб, голосування — 48 годин, кворум — 50%. Кандидат сам погоджується на участь і повинен відповідати поточним вимогам Towny до мера або короля. Виборці фіксуються на початку; один UUID — один голос. Після строку посади вибори може скликати громадянин; достроково — чинний голова. Нічия або брак кворуму потребують повторних виборів, а не випадкового переможця. Звичайний виборець не може скасувати завершені вибори з однозначним результатом.

Результат спочатку зберігається як `PREPARED`, потім плагін викликає штатні події/методи Towny та звіряє фактичного правителя. Штатні Towny-події зміни короля/мера й спадкування `/t dynasty` не повинні обходити республіканські вибори. Для відновлення є `resume` та захищений `abort`, описані в інструкції оновлення.

Пряме витрачання республіканської казни через гаманець, банк чи державне замовлення блокується. Видатки затверджуються бюджетним голосуванням. Раніше підписані васальні податки й погоджені союзні внески виконуються як прийняті зобов’язання. Новий васальний договір республіка схвалює через `/t state vassalvote ДЕРЖАВА ID_ПРОПОЗИЦІЇ`, а підвищення статусу — через `/t state advancevote ДЕРЖАВА СТАТУС`, після чого виборці виконують `/t state vote ID yes`. Особисті рахунки не стають державними.

## Союзи

```text
/t union propose ДЕРЖАВА confederation Назва ІНША_ДЕРЖАВА,ТРЕТЯ_ДЕРЖАВА BASE 0 defense,trade Текст конфедеративного договору...
/t union terms ID_СОЮЗУ
/t state unionvote РЕСПУБЛІКА ID_СОЮЗУ
/t union sign ID_СОЮЗУ ДЕРЖАВА
/t union status ДЕРЖАВА
/t union contribute ID_СОЮЗУ ДЕРЖАВА 10.00
/t union treasury ID_СОЮЗУ
/t union vote propose ID_СОЮЗУ ДЕРЖАВА BUDGET p:UUID BASE 5.00
/t union vote cast ID_ГОЛОСУВАННЯ ДЕРЖАВА yes
/t union vote propose ID_СОЮЗУ ДЕРЖАВА INVITE ІНША_ДЕРЖАВА
/t union join ID_СОЮЗУ ЗАПРОШЕНА_ДЕРЖАВА
/t union leave ID_СОЮЗУ ДЕРЖАВА
/t union debt ID_СОЮЗУ ДЕРЖАВА
```

Типи: `personal`, `real`, `merge`, `confederation`, `federation`, `trade_league`. `/t confed` і `/t federation` підтримують ті самі підкоманди, що `/t union`.

Конфедерація, федерація й торговельна ліга типово потребують 3 незалежних учасників. Персональна та реальна унії потребують двох держав із уже спільним правителем. Плагін не призначає монарха іншої країни через пропозицію союзу.

План підписує кожна держава. Адміністратор не замінює особисту згоду правителя. Республіка видає мандат ради через `unionvote`; він прив’язаний до конкретного тексту й фінансових умов. Запрошення нового учасника затверджується одностайно, потім запрошена держава окремо погоджується на вступ. До згоди вона не голосує. Республіканський представник отримує мандат саме на голос `yes` або `no` через `/t state councilvote ДЕРЖАВА ID_ГОЛОСУВАННЯ yes|no`; вихід із союзу також вимагає внутрішнього рішення `/t state exitvote ДЕРЖАВА ID_СОЮЗУ`. У раді — одна держава, один голос; бюджету потрібно 2/3, конституції, вступу та завершенню союзу — одностайність.

У союзів окрема скарбниця `u:ID`, внески та борги. Вона не має доступу до `r:ВАЛЮТА` або золотих рахунків. Республіканський разовий внесок оформлюється бюджетним рішенням на `u:ID`. Типовий вихід потребує триденного повідомлення й сплати прийнятих внесків. Для федерації односторонній вихід має бути прямо дозволений конституційним маркером `exit:notice`; інакше потрібна конституційна процедура ради. За нестачі учасників союз призупиняється; рада все ще може розподілити кошти й завершити його.

Рішення ради: `CHARTER Текст...`, `INVITE ДЕРЖАВА`, `BUDGET ОДЕРЖУВАЧ ВАЛЮТА СУМА`, `TERMINATE`. Сфери `defense`, `trade` тощо — погоджені політичні повноваження та журнал, а не автоматичне вимкнення PvP, війна або скасування захисту Towny.

## Повне політичне об’єднання

Об’єднавча унія утворює одну політичну державу: колишня держава стає її прямим адміністративним регіоном, утрачає окрему політичну прогресію та зовнішнє підпорядкування. **Об’єкти Towny-націй, UUID міст і привати фізично не зливаються.** Це зберігає чинні права, васальні договори, економіку та можливість звірити журнали. Одна команда не видаляє другу Towny-націю.

Підтриманий точний план:

```text
capital=t:UUID; institutions=charter; rulers=governors; vassals=preserve; budgets=keep; currencies=preserve; territories=provinces
```

`capital` визначає державу-центр за її прямою територією. `rulers=governors` зберігає колишніх місцевих правителів як губернаторів. `institutions=charter` робить цей установчий акт спільним політичним статутом. Для звичайних бюджетів є два варіанти: `keep` зберігає місцеві рахунки в розпорядженні погоджених губернаторів, `sum` переносить звичайні залишки до казни центру. Валюти, золоті рахунки та резерви залишаються окремими в обох варіантах. Чинні васальні договори зберігаються.

Обидві держави спочатку виконують `/t union sign ID ДЕРЖАВА`, потім **кожна окремо** `/t union confirm ID ДЕРЖАВА`. Зміна правителя, територіального складу або статуту анулює можливість застосувати старий план. Однокомандного роз’єднання завершеної держави немає. Для фізичного злиття Towny-націй потрібна окрема, ще не реалізована міграція, узгоджена з правами, договорами та валютою.

## Зручні скорочення й адміністративні виправлення

`/t state progress` і `/t state advance preview` без аргументів показують доступні шляхи власного старшого володіння. `/t castle pos1`, `/t castle pos2`, `/t castle inspect`, `/t castle status`, `/t state charter`, `/t state capital` також приймають власне володіння за замовчуванням. `/t state decisions [володіння]` показує чинні проєкти рішень. Заявка `submit` потребує цільового статусу, якщо є кілька гілок.

Титули посад відображають затверджений політичний статус. `/t title grant` не дозволяє видати титул без власного відповідного володіння й не надає спадкової влади в республіці. Незалежний перевіряльник має право `empirecraft.feudal.castle.review`; виправлення договорів і невизначених передач захищені `empirecraft.feudal.admin`.

## Поетапне заснування конфедерації або федерації

```text
/t confed create Назва_союзу
/t confed invite Держава_Б
/t confed invite Держава_В
/t confed amend ID_СОЮЗУ ДЕРЖАВА_ЗАСНОВНИК Повний текст погодженого конфедеративного договору...
/t union sign ID_СОЮЗУ ДЕРЖАВА
```

Для федерації використовуйте `/t federation create` і ті самі підкоманди. До появи трьох учасників і письмового статуту підписання заблоковане. Кожна зміна складу або тексту проєкту анулює попередні підписи та республіканські мандати; усі погоджуються з новими умовами. Поетапний проєкт починається з нульових внесків і компетенцій `defense,trade`. Для іншої валюти, фінансування чи компетенцій використовуйте повну `/t union propose` із явними умовами. У чинному союзі `invite` створює одностайне рішення ради.

Якщо є кілька союзів, укажіть `/t union invite ID_СОЮЗУ ДЕРЖАВА_ЗАСНОВНИК ЗАПРОШЕНА_ДЕРЖАВА`. `/t federation charter` та `/t federation powers` без ID працюють, коли у вашої держави одна чинна федерація. `/t union terminate ID_СОЮЗУ ДЕРЖАВА` відкриває голосування про завершення; це не одностороннє видалення.

## Провізія та зникнення володінь

Правила `/t provision` наведено в [PROVISIONS.md](PROVISIONS.md). Політичний статус і харчове забезпечення діють разом: політичне об’єднання не переносить фізичні склади між містами й не рахує один Towny-приват двічі. Республіканські грошові витрати потребують голосування; міську їжу, як і раніше, вносять жителі, забирають мер/помічники.

Голодний розпад не блокується власними політичними зв’язками. Після штатного видалення Towny зниклі володіння перестають обкладати/сплачувати поточні адміністративні витрати та голосувати в союзі. Скарбниці, борги й історія архівуються без списання зобов’язань. За втрати об’єднавчого центру вцілілі провінції звільняються від нечинної адміністрації без зміни фізичних Towny-даних. Повторний запуск не повторює ці архівні дії.
