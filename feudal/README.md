## Установлення

1. Зупиніть сервер, збережіть копію даних, приберіть старий JAR цього плагіна та покладіть `server/plugins/empirecraft-feudal-1.4.0.jar` у `plugins/` сервера.
2. Towny має бути встановлений. Для поповнення/виведення базових грошей потрібні Vault та його економічний провайдер, наприклад EssentialsX.
3. Перезапустіть сервер. H2 уже включено до JAR; зовнішніх завантажень під час запуску плагін не потребує.
4. В консолі виконайте `vassal admin check`, а в грі — `/васал допомога` або `/t vassal menu`.

Під час першого запуску імпортуються держави та міста Towny за UUID. Повторний імпорт не створює дублікатів. Наявні баланси, привати й належність міст до держав не змінюються. Установлення само по собі не встановлює платну данину: для неї потрібен погоджений договір.

Налаштування створюються в `plugins/EmpirecraftFeudal/config.yml`. База й журнал — у `plugins/EmpirecraftFeudal/feudal.mv.db`. Файл бази не слід копіювати під час роботи сервера: використайте `/t vassal admin backup` або зупиніть сервер перед копіюванням.

Повністю український початок роботи: `/васал допомога`, `/васал меню`, `/cu balance`, `/титул інфо`. Для адміністратора: `/васал адмін перевірити`, `/васал адмін копія`. Підказки Tab містять українські та англійські назви команд. Якщо `/t title` зайнята стандартною командою Minecraft, використовуйте `/титул` або `/empirecraftfeudal:title`.

## Сумісність із початковою моделлю 1.2

Наведені нижче рівні `Kind` залишаються внутрішніми ідентифікаторами Towny та старої економіки. Починаючи з 1.3, поточний політичний статус зберігається окремо: нове місто або нація починає з поселення. Існуючі володіння зберігають попередні ранги під час міграції. Політичні умови й захист республіканських бюджетів мають пріоритет над старими прикладами команд.

## Що уточнено в початковому плані

- **Внутрішня ієрархія:** держава Towny = королівство, місто Towny = баронство. Герцогства та графства — постійні регіональні володіння всередині держави; нових приватів вони не створюють.
- **Зовнішній васалітет:** королівство може підкоритися іншому королівству, зберігаючи свої міста, короля, валюту й внутрішню ієрархію. Держави Towny при цьому не зливаються.
- **Заснування:** Towny 0.101.2.0 не дозволяє засновувати місто, залишаючись жителем іншого. Тому сюзерен заздалегідь видає триденну грамоту. Гравець виходить із міста, а грамота зберігає погоджені державу й сюзерена. Немає небезпечного автоматичного виходу чи обходу земельних перевірок Towny.
- **Посада та дворянський титул:** політична влада походить від керівництва володінням. `/t title grant` надає дворянський статус, але не передає чужі посади чи привати. Посада графа/герцога передається окремим погодженим призначенням. Короля й мера визначає Towny.
- **Зміна сюзерена:** згоду дають васал, новий сюзерен і попередній сюзерен. Якщо один гравець представляє кілька сторін, його одного підпису достатньо для цих сторін. Адміністративне право не підписує договір замість гравця.
- **Зміна громадянства:** якщо граф чи герцог залишає державу, його регіон переходить під управління корони. Землі, рахунки, підлеглі та договори зберігаються. Старий правитель втрачає доступ до регіональної скарбниці. Це запобігає обнуленню договорів простим виходом із міста.
- **Валюти:** одна державна валюта на емітента; для нових валют плаваючий золотий курс R/M. Старі зобов’язання BASE збережені для погашення. Докладно: [валютна система 1.1](CURRENCY.md). Інші плагіни продовжують користуватися своєю базовою економікою; власні валюти не підміняють Vault для всіх магазинів.

## Володіння й договори

Ієрархія: **король → герцог → граф → барон**. Рівні можна пропускати. Один гравець може керувати кількома володіннями, кожне з окремою скарбницею. У володіння один безпосередній сюзерен. Цикли та зв’язки між внутрішніми регіонами різних держав заборонені.

Назви з пробілами вводьте через `_`. Якщо місто й держава мають однакову назву, використовуйте `місто:Назва` та `держава:Назва`. Незмінний ID можна побачити через `info`.

| Команда | Призначення |
|---|---|
| `/t vassal info [володіння]` | Правитель, держава, сюзерен, підлеглі; власнику — баланс і борг |
| `/t vassal tree [володіння] [сторінка]` | Повне дерево, 20 рядків на сторінку |
| `/t vassal list [володіння]` | Прямі васали |
| `/t vassal liege [володіння]` | Безпосередній сюзерен |
| `/t vassal menu` | Меню власних володінь та гаманця |
| `/t vassal create <сюзерен> <герцогство\|графство> <назва>` | Створити регіон; спочатку ним керує засновник |
| `/t vassal appoint <регіон> <гравець>` | Запропонувати передачу регіональної посади |
| `/t vassal offer <васал> <сюзерен> <данина> <код> [автономія] [військовий_обов’язок] [дні]` | Запропонувати новий договір або зміну чинного |
| `/t vassal petition <васал> <сюзерен> <данина> <код>` | Подати прошення від імені васала |
| `/t vassal offers` | Умови, ID, необхідні та наявні підписи |
| `/t vassal accept <ID>` | Підписати пропозицію |
| `/t vassal reject <ID>` | Відхилити/скасувати пропозицію |
| `/t vassal contract [володіння]` | Чинні умови, строк і дата наступної данини |
| `/t vassal release <васал>` | Сюзерен добровільно завершує договір |
| `/t vassal independence <володіння>` | Запит на мирну незалежність, який приймає сюзерен |
| `/t vassal history [володіння]` | Останні 20 записів журналу для правителя |

Автономія: `висока` або `обмежена`. Висока дозволяє регіональному правителю створювати нижчі регіони й видавати грамоти. Право корони створювати володіння зберігається. Військовий обов’язок: `добровільно`, `оборона`, `повний`; ці поля описують погоджений обов’язок для відіграшу й не створюють автоматичної війни, NPC чи примусових телепортацій. Строк: `0` — безстроково або `7–365` реальних днів. Типово пропозиція діє 48 годин.

Приклад для короля:

```text
/t vassal create держава:Русь герцогство Київське
/t vassal appoint Київське ІмяГерцога
```

Потрібні правителі, зокрема кандидат, переглядають `/t vassal offers` і підписують `/t vassal accept <ID>`. Для підпорядкування міста:

```text
/t vassal offer місто:Черкаси Київське 50.00 BASE висока оборона 0
```

Мер, герцог і корона погоджують перехід своїми підписами. До завершення підписання місто має попереднього сюзерена та попередні умови.

## Грамота на заснування

```text
/t vassal charter держава:Русь ІмяГравця
```

Король видає грамоту громадянину своєї держави; герцог/граф — за високої автономії. Далі гравець самостійно залишає старе місто засобами Towny й виконує:

```text
/t vassal preview Нове_Місто
/t vassal found Нове_Місто
```

Плагін викликає звичайну команду Towny від імені самого гравця. Towny перевіряє право на заснування, зайнятість землі, біом, відстані, ціну та інші обмеження. Якщо Towny вимагає підтвердження оплати, гравець виконує його звичайним способом. Попередня перевірка — інформаційна; вона не гарантує, що всі правила Towny дозволять завершити заснування.

Після успіху використовується штатна процедура вступу до держави з перевіркою лімітів, санкцій, кількості жителів і відстані до столиці. Якщо вступ не дозволений, створене місто зберігається; після усунення причини можна завершити `/t vassal found confirm`. Незавершене заснування переживає перезапуск у межах строку грамоти. За замовчуванням діє додатковий ліміт у 2048 блоків до найближчого привату держави.

## Гаманець, валюти й скарбниці

Актуальні правила, команди, ринок і черга друку: [CURRENCY.md](CURRENCY.md). Старі приклади `/wallet`, `/bank`, `/exchange` з попередніх версій замінені командами `/cu`; команди міської казни перенесено до `/t treasury`.

## Данина та борги

- Перший рахунок — через сім реальних діб після підписання. Далі — за тими самими інтервалами.
- Рахунок унікальний за договором і строком. Перезапуск не створює повторного рахунку чи платежу.
- Платить внутрішня скарбниця васала безпосередній скарбниці сюзерена. Особистий баланс правителя не списується автоматично.
- За достатнього балансу рахунок сплачується автоматично; інакше зберігається борг. Можлива часткова ручна сплата.
- Типовий ліміт — два несплачені періоди на договір. Після тривалого простою періоди понад ліміт прощаються з окремим записом журналу; борг не росте нескінченно.
- Звільнення або заміна договору зберігає вже виставлені борги й спочатку нараховує рахунки, строк яких уже настав.
- Плагін не видаляє міст і не забирає привати через борги. Військові санкції та повстання залишено наступним етапам.

```text
/t vassal tribute status місто:Черкаси
/t vassal tribute pay місто:Черкаси 25.50 BASE
```

Towny-команди виходу міста, вигнання, видалення й злиття заблоковані, поки вони обходять чинний договір або несплачений борг. Спершу завершіть відносини й погасіть зобов’язання. Зміни, зроблені поза плагіном або іншими модами без стандартних Towny-подій, узгоджуються під час наступної синхронізації; зниклі об’єкти архівуються, а не видаляються з фінансової історії.

## Адміністрування та збої

Для тестування розвитку доступні `/t state debug next`, `setstage`, `government`, `territory`, `ready` та `info`. Потрібен окремий дозвіл `empirecraft.feudal.debug` (типово для OP). Консольна команда — `statedebug`. Приклади й повний синтаксис: [STATE-DEBUG.md](STATE-DEBUG.md).

`empirecraft.feudal.use` типово доступне всім. Право користуватися конкретною владною командою додатково перевіряється за чинною посадою та межами володіння. `empirecraft.feudal.admin` типово лише для операторів.

```text
/t vassal admin preview
/t vassal admin import
/t vassal admin check
/t vassal admin backup
/t vassal admin setliege <васал> <сюзерен>
/t vassal admin release <васал>
/t vassal admin pending
/t vassal admin vault <ID> applied
/t vassal admin vault <ID> failed
```

`setliege` — адміністративне виправлення зі збереженням журналу та перевіркою циклів. Воно завершує попередній договір, зберігає борги й встановлює зв’язок без нової платної данини.

Vault не має універсального ідентифікатора повторюваного платежу. Тому перед зовнішнім викликом зберігається стійка операція `PREPARED`; при виведенні BASE резервується. Після відомої відповіді операція завершується атомарно. Якщо сервер упав між зовнішнім списанням і фіксацією результату, виклик **не повторюється автоматично**. Нові зовнішні перекази цього гравця блокуються до перевірки журналу провайдера. Адміністратор позначає `applied`, якщо зовнішній переказ справді відбувся, або `failed`, якщо ні. Повторне завершення заборонене. Ці команди не слід застосовувати навмання.

## Старі меню та подальші етапи

У `titles.yml` і `tituls_plat.yml` замінено 30 викликів `lp ... meta clear` на `meta removesuffix 1`. Вибір косметичного титулу більше не очищає всі префікси й метадані. Ці меню не надають феодальну владу.

Перший реліз охоплює основу, імпорт, дерево, договори, скарбниці, забезпечені валюти та данину. Окремими наступними змінами залишаються валютна біржа, фізичні монети, династії та спадкування, війни за незалежність, регіональні полігони JourneyMap і повне оформлення TAB. Наявний міст JourneyMap продовжує відображати території Towny; цей плагін не змінює його протокол.

## Збірка й перевірки

Потрібні JDK 17+ та Python 3:

```sh
python feudal/build.py
```

Скрипт завантажує лише зафіксовані API й H2, перевіряє SHA-256, компілює з `--release 17`, запускає інтеграційні тести справжньої H2 та створює відтворюваний JAR у `server/plugins/`. Потрібен мережевий доступ тільки під час першої збірки, якщо залежності ще відсутні. В `lib/` зберігається кеш, який не додається до git. SHA-256 готового JAR лежить поруч із ним.

H2 2.2.224 включено в JAR зі збереженням його ліцензійних файлів. Результати перевірок сумісності дивіться в `validation/feudal-system.json`.

Перевірено 53 сценарії на справжній H2 та 4 сценарії планування інвентарю, зокрема повну ієрархію, підписи всіх сторін, права на скарбниці, резерв валют, повторний запуск і відновлення онлайн-копії бази. Компіляція використовує точний Towny JAR із репозиторію та Spigot API 1.20.1. Це не є тестом запуску Mohist: живий Mohist 71a84ff7, підключення гравця, меню та взаємодія з усім набором плагінів у цій перевірці не запускалися.
