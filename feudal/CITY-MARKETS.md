# Міські ринки — EmpirecraftFeudal 1.9.0

Реалізація в наявному Bukkit-плагіні Minecraft 1.20.1 / Towny 0.101.2.0. Новий вхід — `/market menu` або `/ринок menu`. Основне меню використовує звичайний інвентар Minecraft; форми операцій — команди з попереднім переглядом і підтвердженням на 60 секунд. Для цього меню не потрібне оновлення клієнтського моста.

## Установлення та міграція

1. Завершити відомі невизначені передачі через `/commerce pending`, `inspect`, `recover` або `abort`. Якщо стара відкрита заявка має незавершену передачу, міграція зупиняє запуск плагіна; вона не вгадує результат інвентарю.
2. Зупинити сервер і зберегти резервну копію каталогу `plugins/EmpirecraftFeudal`, playerdata та конфігурації. Замінити лише старий `empirecraft-feudal-*.jar` на `empirecraft-feudal-1.9.0.jar`; залишити БД та інші плагіни на місці.
3. Переглянути нову секцію `markets` у конфігурації: радіус стійки 6, до 64 чанків, до 200 звичайних записів активів перед новим депозитом, дозволений каталог ресурсів. Заборона нового депозиту не блокує повернення власного майна.
4. Запустити сервер. Перед першим створенням таблиць ринків плагін робить узгоджену H2-копію `backups/before-city-markets-*.zip`.
5. Старі відкриті глобальні замовлення стають `MIGRATED`. Невитрачений резерв повертається законному рахунку один раз. Уже поставлені предмети залишаються в старому обліку, їхня кількість не обнуляється міграцією.
6. Для старих предметів адміністратор встановлює початкове місце зберігання за журналами й підтверджує його особисто: `/market admin legacy РИНОК СТАРЕ_ЗАМОВЛЕННЯ підстава_визначення_місця`. Це переносить запис власності в місцеве сховище, а не предмети між містами. Відсутність координат у старій глобальній заявці не можна автоматично виправити достовірно; не призначайте довільне нове місце. Повторне перенесення не створює активів.

Плагін не запускає міграцію над файлами серверного світу під час збирання. Наданий JAR — окремий результат збирання; робочий сервер у цьому завданні не запускався.

## Відкриття ринку

Приклади нижче вводяться без кутових дужок. `ID` — UUID, отриманий від попередньої команди. Кожна команда зміни показує підтвердження `/market confirm ТОКЕН`.

1. Мер: `/market founding create Київський_ринок опис комплексу`.
2. Адміністратор додає міські чанки: `/market admin claims ID add 10 20 причина`. Зона має бути зв’язною сторонами, в одному вимірі й без перетину з іншими ринками. Зміна меж проєкту повертає його на доопрацювання.
3. Для кожного побудованого відділу адміністратор дивиться на блок його стійки й реєструє окремі межі: `/market admin department ID GOODS building x1 y1 z1 x2 y2 z2 причина`. Типи: `GOODS`, `FX`, `JOBS`, `CREDIT`. Межі включають зазначені крайні блоки, а будівлі різних відділів не перетинаються. Максимальний обсяг однієї будівлі — 200000 блоків.
4. Мер: `/market founding submit ID`.
5. Адміністратор особисто оглядає кожну будівлю зсередини: `/market admin department ID GOODS approve результат_огляду`. Для огляду потрібні завантажені чанки; порожня ділянка не приймається.
6. Адміністратор: `/market admin inspect ID`, потім `/market admin approve ID результат_огляду`. Достатньо одного окремо схваленого відділу. За замовчуванням місто має один відкритий або призупинений ринок. Окреме адміністративне збільшення: `/market admin city_limit ID новий_ліміт причина`.
7. Мер дозволяє платіжну валюту: `/market manage ID payment KRN true`. Це окремо від біржових допусків.

Для нової операції сервер повторно перевіряє світ, міський чанк, стан ринку, відповідну будівлю, стійку й тривимірну відстань. Наявність відкритого меню нічого не дозволяє сама по собі.

Знищення зареєстрованої стійки блокує відділ. На схваленні також зберігається до 256 контрольних блоків будівлі: втрата щонайменше половини підтверджує руйнування. Перевірка не завантажує чанки й не вважає вивантаження руйнуванням. Інші випадки непридатності адміністратор підтверджує оглядом і командою `department ... suspend причина`. Відбудова потребує повторного `approve`.

## Товари, отримання та тарифи

- `/market book` — місцеві заявки; `/market inspect_lot ID` — безпечний перегляд повного ItemStack без можливості забрати іконку.
- Точний зразок у руці: `/market sell 256 KRN 2.00 3`, `/market buy 128 KRN 2.50 3`.
- Купівля без зразка за побаченою специфікацією: `/market buy 1 KRN 20.00 1 specID`.
- Строки заявок: 1, 3 або 7 реальних діб. Ціна за предмет має точність до 0.01. Унікальні нестековані предмети — тільки окремі лоти кількістю 1. Ресурси допускаються конфігураційним каталогом, але порівняння все одно враховує весь збережений ItemStack.
- Контейнери, BlockStateMeta, карти із зовнішнім вмістом і bundle не приймаються у цій версії. Перевірка специфічних модових ItemStack на справжньому сервері залишається частиною приймання.
- `/market orders`, `/market cancel ID`, `/market reduce ID новий_залишок`. Зменшення зберігає пріоритет; зміна ціни потребує скасування та нової заявки.
- `/market assets` або `/market load` — особисті активи. `/market load ID [кількість]` — отримання біля стійки відділу походження. Предмети не випадають на землю; за повного інвентарю передача не починається.
- Скасування, строк або поліпшення ціни повертають залишок у сховище того самого ринку, не дистанційно в гаманець.
- `/market manage ID tariff 0 200 200` — нові ставки покупця, продавця та послуг у базисних пунктах, діапазон 0–500. Вони набувають чинності через 24 години. Кожна стара заявка й контракт зберігають власну версію.
- Збір рахується від накопиченої виконаної суми, без повторного округлення кожної частини. За розміщення, скасування та звичайне отримання збору немає.

Пріоритет заявки виникає після фактичного внесення предметів. Ціна угоди — ціна заявки, що вже стояла в книзі. Самозіставлення не створює угод: залишок нової перехресної власної заявки скасовується.

## Валютна біржа й відомості

Мер: `/market manage ID host KRN true`. Банкір емітента: `/market exchange permit ID KRN issuer true`. Обидві валюти пари потребують обох допусків. Відкликання скасовує лише відповідні залишки, не вилучає виручку й не змінює борги.

Одна основна книга на неупорядковану пару: коди впорядковані за абеткою. `KRN/SOL` означає SOL за одну KRN. `/market exchange buy KRN SOL 20 2.10 3` резервує SOL; `sell` вносить KRN. Лот — одна ціла базова монета; ціна у котируваній валюті має два десяткові знаки. `/market exchange inverse` показує зворотний напрямок тієї самої книги, без другої ліквідності.

`/market exchange orders` показує місцеву глибину. `/market exchange chart 1|24|168|720` — графік фактичних угод у чаті з 24 часовими проміжками, прогалинами й обсягом. Остання угода не підміняє доступну пропозицію. Приватний FX переміщує тільки вже випущені монети; золоті резерви та емісія не змінюються.

Перебування в ринкових чанках відкритого Валютного відділу оновлює персональні знімки не частіше одного разу на 30 секунд. `/market exchange rates` поза ринком показує лише відомі знімки з початковою датою, давністю й попередженням. Порожня книга також записується. `/market share_info гравець`, потім у отримувача `/market share_info accept`: обидва онлайн у межах 8 блоків. Передавання не змінює номер і дату спостереження й не копіює баланси чи борги.

Глобальний `/cu exchange` спрямовує до ринку, старі приватні coin-to-coin виклики заблоковано також у сервісному шарі й старому UI. Окремі банківські операції залишаються: `/cu bank quote|convert кількість_злитків @GOLD КОД`, `/cu redeem сума КОД`, резерв і друк емітента. Це банківські операції з власною ліквідністю, кривими й комісіями, а не виконання приватної місцевої заявки. `/cu pay` залишається прямим переказом. Старі `/trade` і `/order` не створюють обходу ринку.

## Роботи та постачання

- `/market jobs supply KRN 100.00 3 100 true Залізо для мосту` — точний зразок у руці; `true` дозволяє часткову поставку.
- `/market contract ID deliver 30` — фізичне здавання в JOBS; за недоступної будівлі й відкритого пункту повернення: `contract ID recover 30`.
- `/market jobs work KRN 100.00 7 40.00:Опори;60.00:Готовий_прохід опис результату, координати та правила приймання` — резерв усієї оплати, 1–20 етапів, сума етапів дорівнює винагороді.
- `/market contract ID accept`, `submit 1 докази`, `approve`, `dispute причина`.
- Після прийняття роботи одностороннє `cancel` недоступне. Відсутність реакції протягом 48 годин або прострочення роботи переводить її в спір; гроші залишаються в резерві.
- Незалежний адміністратор: `/market contract ID arbitrate сума_виконавцю причина`. Розподіляється лише фактичний залишок резерву; міський збір утримується з виплати виконавцю.
- Погоджені зміни опису та строку: `/market contract ID amend дні новий_опис`; погоджене розірвання: `contract ID terminate сума_виконавцю причина`. Друга сторона спочатку переглядає `/market agreement ID_ПРОПОЗИЦІЇ`, потім підписує `agreement accept ID_ПРОПОЗИЦІЇ`.

Зміна етапів або їх фінансових сум після прийняття в цьому інтерфейсі не передбачена: можна погоджено завершити стару роботу й створити новий профінансований контракт. Контракт не перевозить вантаж між містами.

## Заставні кредити

1. Кредитор: `/market loan license_apply РИНОК KRN`. Мер: `/market loan license_requests РИНОК`.
2. Мер тримає допустимий точний зразок застави: `/market loan license РИНОК кредитор KRN 1000.00 5000.00 1000 30 5 true`. Це максимальна позика, сукупний непогашений основний борг, ставка за весь строк у б.п., дні та число виданих/схвалених позик. Одна ліцензія на валюту визначає одну точну специфікацію застави.
3. Кредитор вносить капітал біля CREDIT: `/market loan deposit РИНОК KRN 500.00`. `/market loan withdraw РИНОК KRN 100.00` звільняє лише вільний залишок до місцевого отримання. `/market loan funds` — власні фонди.
4. Пропозиція зі зразком застави в руці: `/market loan offer РИНОК KRN 100.00 800 14 64` — 100 монет, 8% за весь строк, 14 діб, 64 предмети застави.
5. Позичальник: `/market loan offers`, `loan apply ID_ПРОПОЗИЦІЇ`. Кредитор: `loan applications`, `loan approve ID_ПОЗИКИ`. Гроші й ліміти резервуються відразу; через 24 години неотримане схвалення скасовується без боргу.
6. Позичальник особисто в CREDIT: `/market loan take ID`. Підтвердження показує всю суму повернення, заставу, строк, пільгу й наслідки. Застава фіксується окремо, вся основна сума надходить до гаманця, запускається строк.
7. `/market loan mine`; дистанційно `/market loan repay ID сума`. Спочатку погашаються погоджені відсотки, потім основна сума. Дострокове погашення не зменшує фіксовані відсотки. Платіж кредитору надходить у сховище ринку, а не створює нові монети.
8. Після повного погашення вся застава повертається позичальнику до отримання. Після дати платежу й 24 годин пільги кредитор може виконати `/market loan foreclose ID`: вся застава закриває весь залишок боргу. До фактичного стягнення оплата можлива. Обидві дії не можуть виконатися двічі.
9. Продовження строку без зміни номіналу, відсотків чи застави: `/market loan extend ID дні`, потім підпис другої сторони через `agreement`. Пропозиція сама по собі не зупиняє старий строк.

`/market loan cancel ID` дозволяє стороні відмовитися від заявки або ще неотриманого схвалення зі звільненням резерву; виданий борг таким способом не скасовується. `/market loan offer_close ID` закриває власну пропозицію для нових заявок.

Відкликання ліцензії (`false`) звільняє лише неотримані схвалення відповідної валюти; чинні борги, застави й платежі залишаються. Публічні пропозиції не містять чужих балансів; загальну кредитну історію позичальника цей інтерфейс не розкриває. Беззаставних позик немає.

## Призупинення, повернення й надійність

`/market admin suspend ID причина` зупиняє нову економіку й зіставлення; `close` скасовує залишки заявок і неотримані схвалення, але зберігає чинні позики й контракти. `archive` перевіряє відсутність чинних зобов’язань. Закритий ринок не відкривається повторно. Межі вже відкритого ринку не переносяться.

За недоступного відділу `/market recover ID_АКТИВУ` повертає гроші дистанційно. Для предметів адміністратор відкриває `/market admin recovery РИНОК` на початковій території та забезпечує фактичний доступ власникам; отримання предметів залишається на цій території. Ринок не використовують для телепортації вантажів. Місто не отримує право на приватне майно через зміну мера.

Резерви, виплати, збори й історія змінюються в одній H2-транзакції. `cm_actions` фіксує ID дії, автора, відбиток параметрів і результат. `cm_ledger` записує рух коштів із балансами до/після. Усі монети залишаються в загальній таблиці `accounts`, отже включаються в облік M; борг та очікувані відсотки не є балансом.

Передача інвентарю використовує наявні `item_ops`/`item_participants`: постійні знімки до/після, блокування подальших дій за невизначеного результату, явне відновлення `/commerce inspect|recover|abort`. Видача зі сховища резервує кількість до зміни інвентарю. Повтор завершення нової ринкової передачі не дублює активи. Для багатозначного результату потрібне узгодження адміністратора, а не сліпе повторення видачі.

Contact залишено **вимкненим**. Адаптер власності ящика, життєвого циклу й надійного підтвердження доставлення не реалізовано без перевірки встановленого Contact API; у меню це прямо пояснено. Економіка не залежить від пошти. Відомий зв’язок акаунтів адміністратор реєструє командою `/market admin related РИНОК гравець1 гравець2 підстава`. Їхні угоди отримують позначку `FILL_REVIEW` у службовому журналі. Система не обіцяє автоматично виявляти альтернативні акаунти.

## Збирання й приймання

Звичайний шлях: `python feudal/build.py` із JDK 17+. Залежності закріплено SHA-256. Для окремого результату без заміни плагінів сервера додайте `--output-dir /шлях/до/результату`.

У наданому середовищі Spigot-host недоступний за мережевою політикою, тому використано встановлений API Mohist із SHA-256 `cacaee7a156c57c457db3bde9cb2dfc9ea7e69459458f22ea7f6ee889a7266a7`:

```bash
JAVA_HOME=/workspace/.empirecraft/jdk-17 python feudal/build.py \
  --server-api server/libraries/net/minecraftforge/forge/1.20.1-47.4.23/forge-1.20.1-47.4.23-universal.jar \
  --api-libraries server/libraries \
  --output-dir work/market-release
```

Перевірки охоплюють реальну H2, незмінність емісії, арифметику зборів, права, фізичні координати, локальні книги, ідемпотентність, відновлення, міграцію, кредити та спори. `CityMarketTests` додає 38 сценаріїв. Старі валютні тести підтверджень використовують окремі дані особи й дозволів, не проксі всього Forge Player API; їхні перевірки збережено.

Окремо на копії справжнього сервера потрібно пройти взаємодію з інвентарним меню, руйнування/вивантаження будівель, Towny-заборони входу й пункт повернення, збереження конкретних модових предметів та аварійне завершення між `saveData` і SQL-фіксацією. Автоматичні перевірки моделі не замінюють ці перевірки Minecraft.
