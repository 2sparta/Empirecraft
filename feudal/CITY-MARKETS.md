# Міські ринки — EmpirecraftFeudal 1.14.0

Реалізація в наявному Bukkit-плагіні Minecraft 1.20.1 / Towny 0.101.2.0. Вхід — `/market menu` або `/ринок menu`. Основне меню — нативний екран Forge з формами, переглядом точних предметів, графіками й окремим підтвердженням на 60 секунд. Потрібен `empirecraft-towny-journeymap-1.9.0.jar` з однаковими байтами у клієнтському та серверному `mods`. Команди залишаються додатковим входом до тих самих перевірок; інвентарне меню прибране. [Корабельний ринок і аукціони](../naval/README.md) відкриваються через `/market ships` і додатково потребують Sails 17.

## Установлення та міграція

1. Завершити відомі невизначені передачі через `/commerce pending`, `inspect`, `recover` або `abort`. Якщо стара відкрита заявка має незавершену передачу, міграція зупиняє запуск плагіна; вона не вгадує результат інвентарю.
2. Зупинити сервер і зберегти резервну копію каталогу `plugins/EmpirecraftFeudal`, playerdata та конфігурації. Замінити лише старий `empirecraft-feudal-*.jar` на `empirecraft-feudal-1.13.2.jar`; залишити БД та інші плагіни на місці.
3. На обох сторонах замінити старий `empirecraft-towny-journeymap-*.jar` на міст **1.8.1**, а `townyrecruits-*.jar` — на **1.0.4**. В активному каталозі лишити по одному JAR кожного мода. Оновити клієнтський список ADM зі збірки разом із цими файлами.
4. Переглянути нову секцію `markets` у конфігурації: радіус стійки 6, до 64 чанків, до 200 звичайних записів активів перед новим депозитом, дозволений каталог ресурсів. Заборона нового депозиту не блокує повернення власного майна.
5. Запустити сервер. Перед першим створенням таблиць ринків плагін робить узгоджену H2-копію `backups/before-city-markets-*.zip`.
6. Старі відкриті глобальні замовлення стають `MIGRATED`. Невитрачений резерв повертається законному рахунку один раз. Уже поставлені предмети залишаються в старому обліку, їхня кількість не обнуляється міграцією.
7. Для старих предметів адміністратор встановлює початкове місце зберігання за журналами й підтверджує його особисто: `/market admin legacy РИНОК СТАРЕ_ЗАМОВЛЕННЯ підстава_визначення_місця`. Це переносить запис власності в місцеве сховище, а не предмети між містами. Відсутність координат у старій глобальній заявці не можна автоматично виправити достовірно; не призначайте довільне нове місце. Повторне перенесення не створює активів.

Плагін не запускає міграцію над файлами серверного світу під час збирання. Наданий JAR — окремий результат збирання; робочий сервер у цьому завданні не запускався.

## Відкриття ринку

Приклади нижче вводяться без кутових дужок. `ID` — UUID, отриманий від попередньої команди. Кожна команда зміни показує підтвердження `/market confirm ТОКЕН`.

1. Мер: `/market founding create Київський_ринок опис комплексу`.
2. Адміністратор додає міські чанки: `/market admin claims ID add 10 20 причина`. Зона має бути зв’язною сторонами, в одному вимірі й без перетину з іншими ринками. Зміна меж проєкту повертає його на доопрацювання.
3. Для кожного побудованого відділу адміністратор дивиться на блок його стійки й реєструє окремі межі: `/market admin department ID GOODS building x1 y1 z1 x2 y2 z2 причина`. Типи: `GOODS`, `FX`, `JOBS`, `CREDIT`. Межі включають зазначені крайні блоки, а будівлі різних відділів не перетинаються. Максимальний обсяг однієї будівлі — 200000 блоків.
4. Мер: `/market founding submit ID`.
5. Адміністратор особисто оглядає кожну будівлю зсередини: `/market admin department ID GOODS approve результат_огляду`. Для огляду потрібні завантажені чанки; порожня ділянка не приймається.
6. Адміністратор: `/market admin inspect ID`, потім `/market admin approve ID результат_огляду`. Достатньо одного окремо схваленого відділу. За замовчуванням місто має один відкритий або призупинений ринок. Окреме адміністративне збільшення: `/market admin city_limit ID новий_ліміт причина`.
7. Мер дозволяє платіжну валюту: `/market manage ID payment KRN true`. Це окремо від біржових допусків.

Для нової операції сервер повторно перевіряє світ, міський чанк, стан ринку, відповідну будівлю, стійку й тривимірну відстань. Наявність відкритого меню нічого не дозволяє сама по собі.

Знищення зареєстрованої стійки блокує відділ. На схваленні також зберігається до 256 контрольних блоків будівлі: втрата щонайменше половини підтверджує руйнування. Перевірка не завантажує чанки й не вважає вивантаження руйнуванням. Інші випадки непридатності адміністратор підтверджує оглядом і командою `department ... suspend причина`. Відбудова потребує повторного `approve`.

## Товари, отримання та тарифи

- `/market book` — місцеві заявки; `/market inspect_lot ID` — безпечний перегляд повного ItemStack без можливості забрати іконку.
- Точний зразок у руці: `/market sell 256 KRN 2.00 3`, `/market buy 128 KRN 2.50 3`.
- Купівля без зразка за побаченою специфікацією: `/market buy 1 KRN 20.00 1 specID`.
- Строки заявок: 1, 3 або 7 реальних діб. Ціна за предмет має точність до 0.01. Унікальні нестековані предмети — тільки окремі лоти кількістю 1. Ресурси допускаються конфігураційним каталогом, але порівняння все одно враховує весь збережений ItemStack.
- Контейнери, BlockStateMeta, карти із зовнішнім вмістом і bundle не приймаються у цій версії. Перевірка специфічних модових ItemStack на справжньому сервері залишається частиною приймання.
- `/market orders`, `/market cancel ID`, `/market reduce ID новий_залишок`. Зменшення зберігає пріоритет; зміна ціни потребує скасування та нової заявки.
- `/market assets` або `/market load` — особисті активи. `/market load ID [кількість]` — отримання біля стійки відділу походження. Предмети не випадають на землю; за повного інвентарю передача не починається.
- Скасування, строк або поліпшення ціни повертають залишок у сховище того самого ринку, не дистанційно в гаманець.
- `/market manage ID tariff 0 200 200` — нові ставки покупця, продавця та послуг у базисних пунктах, діапазон 0–500. Вони набувають чинності через 24 години. Кожна стара заявка й контракт зберігають власну версію.
- Збір рахується від накопиченої виконаної суми, без повторного округлення кожної частини. За розміщення, скасування та звичайне отримання збору немає.

Пріоритет заявки виникає після фактичного внесення предметів. Ціна угоди — ціна заявки, що вже стояла в книзі. Самозіставлення не створює угод: залишок нової перехресної власної заявки скасовується.

## Валютна біржа й відомості

Мер: `/market manage ID host KRN true`. Банкір емітента: `/market exchange permit ID KRN issuer true`. Обидві валюти пари потребують обох допусків. Відкликання скасовує лише відповідні залишки, не вилучає виручку й не змінює борги.

Одна основна книга на неупорядковану пару: коди впорядковані за абеткою. `KRN/SOL` означає SOL за одну KRN. `/market exchange buy KRN SOL 20 2.10 3` резервує SOL; `sell` вносить KRN. Лот — одна ціла базова монета; ціна у котируваній валюті має два десяткові знаки. `/market exchange inverse` показує зворотний напрямок тієї самої книги, без другої ліквідності.

`/market exchange orders` показує місцеву глибину. `/market exchange chart 1|24|168|720` — графік фактичних угод у чаті з 24 часовими проміжками, прогалинами й обсягом. Остання угода не підміняє доступну пропозицію. Приватний FX переміщує тільки вже випущені монети; золоті резерви та емісія не змінюються.

Перебування в ринкових чанках відкритого Валютного відділу оновлює персональні знімки не частіше одного разу на 30 секунд. `/market exchange rates` поза ринком показує лише відомі знімки з початковою датою, давністю й попередженням. Порожня книга також записується. `/market share_info гравець`, потім у отримувача `/market share_info accept`: обидва онлайн у межах 8 блоків. Передавання не змінює номер і дату спостереження й не копіює баланси чи борги.

Глобальний `/cu exchange` спрямовує до ринку, старі приватні coin-to-coin виклики заблоковано також у сервісному шарі й старому UI. Купівля монет за золото через `bank quote|convert @GOLD → КОД` закрита також на рівні сервісу. Погашення `/cu redeem сума КОД`, внесення до резерву й друк емітента збережені. Офіційний обмін монет між валютами має окремий реально профінансований фонд. `/cu pay` залишається прямим переказом. Старі `/trade` і `/order` не створюють обходу ринку.

## Роботи та постачання

- `/market jobs supply KRN 100.00 3 100 true Залізо для мосту` — точний зразок у руці; `true` дозволяє часткову поставку.
- `/market contract ID deliver 30` — фізичне здавання в JOBS; за недоступної будівлі й відкритого пункту повернення: `contract ID recover 30`.
- `/market jobs work KRN 100.00 7 40.00:Опори;60.00:Готовий_прохід опис результату, координати та правила приймання` — резерв усієї оплати, 1–20 етапів, сума етапів дорівнює винагороді.
- `/market contract ID accept`, `submit 1 докази`, `approve`, `dispute причина`.
- Після прийняття роботи одностороннє `cancel` недоступне. Відсутність реакції протягом 48 годин або прострочення роботи переводить її в спір; гроші залишаються в резерві.
- Незалежний адміністратор: `/market contract ID arbitrate сума_виконавцю причина`. Розподіляється лише фактичний залишок резерву; міський збір утримується з виплати виконавцю.
- Погоджені зміни опису та строку: `/market contract ID amend дні новий_опис`; погоджене розірвання: `contract ID terminate сума_виконавцю причина`. Друга сторона спочатку переглядає `/market agreement ID_ПРОПОЗИЦІЇ`, потім підписує `agreement accept ID_ПРОПОЗИЦІЇ`.

Зміна етапів або їх фінансових сум після прийняття в цьому інтерфейсі не передбачена: можна погоджено завершити стару роботу й створити новий профінансований контракт. Контракт не перевозить вантаж між містами.

## Заставні кредити

1. Кредитор: `/market loan license_apply РИНОК KRN`. Мер: `/market loan license_requests РИНОК`.
2. Мер тримає допустимий точний зразок застави: `/market loan license РИНОК кредитор KRN 1000.00 5000.00 1000 30 5 true`. Це максимальна позика, сукупний непогашений основний борг, ставка за весь строк у б.п., дні та число виданих/схвалених позик. Одна ліцензія на валюту визначає одну точну специфікацію застави.
3. Кредитор вносить капітал біля CREDIT: `/market loan deposit РИНОК KRN 500.00`. `/market loan withdraw РИНОК KRN 100.00` звільняє лише вільний залишок до місцевого отримання. `/market loan funds` — власні фонди.
4. Пропозиція зі зразком застави в руці: `/market loan offer РИНОК KRN 100.00 800 14 64` — 100 монет, 8% за весь строк, 14 діб, 64 предмети застави.
5. Позичальник: `/market loan offers`, `loan apply ID_ПРОПОЗИЦІЇ`. Кредитор: `loan applications`, `loan approve ID_ПОЗИКИ`. Гроші й ліміти резервуються відразу; через 24 години неотримане схвалення скасовується без боргу.
6. Позичальник особисто в CREDIT: `/market loan take ID`. Підтвердження показує всю суму повернення, заставу, строк, пільгу й наслідки. Застава фіксується окремо, вся основна сума надходить до гаманця, запускається строк.
7. `/market loan mine`; дистанційно `/market loan repay ID сума`. Спочатку погашаються погоджені відсотки, потім основна сума. Дострокове погашення не зменшує фіксовані відсотки. Платіж кредитору надходить у сховище ринку, а не створює нові монети.
8. Після повного погашення вся застава повертається позичальнику до отримання. Після дати платежу й 24 годин пільги кредитор може виконати `/market loan foreclose ID`: вся застава закриває весь залишок боргу. До фактичного стягнення оплата можлива. Обидві дії не можуть виконатися двічі.
9. Продовження строку без зміни номіналу, відсотків чи застави: `/market loan extend ID дні`, потім підпис другої сторони через `agreement`. Пропозиція сама по собі не зупиняє старий строк.

`/market loan cancel ID` дозволяє стороні відмовитися від заявки або ще неотриманого схвалення зі звільненням резерву; виданий борг таким способом не скасовується. `/market loan offer_close ID` закриває власну пропозицію для нових заявок.

Відкликання ліцензії (`false`) звільняє лише неотримані схвалення відповідної валюти; чинні борги, застави й платежі залишаються. Публічні пропозиції не містять чужих балансів; загальну кредитну історію позичальника цей інтерфейс не розкриває. Беззаставних позик немає.

## Призупинення, повернення й надійність

`/market admin suspend ID причина` зупиняє нову економіку й зіставлення; `close` скасовує залишки заявок і неотримані схвалення, але зберігає чинні позики й контракти. `archive` перевіряє відсутність чинних зобов’язань. Закритий ринок не відкривається повторно. Межі вже відкритого ринку не переносяться.

За недоступного відділу `/market recover ID_АКТИВУ` повертає гроші дистанційно. Для предметів адміністратор відкриває `/market admin recovery РИНОК` на початковій території та забезпечує фактичний доступ власникам; отримання предметів залишається на цій території. Ринок не використовують для телепортації вантажів. Місто не отримує право на приватне майно через зміну мера.

Резерви, виплати, збори й історія змінюються в одній H2-транзакції. `cm_actions` фіксує ID дії, автора, відбиток параметрів і результат. `cm_ledger` записує рух коштів із балансами до/після. Усі монети залишаються в загальній таблиці `accounts`, отже включаються в облік M; борг та очікувані відсотки не є балансом.

Передача інвентарю використовує наявні `item_ops`/`item_participants`: постійні знімки до/після, блокування подальших дій за невизначеного результату, явне відновлення `/commerce inspect|recover|abort`. Видача зі сховища резервує кількість до зміни інвентарю. Повтор завершення нової ринкової передачі не дублює активи. Для багатозначного результату потрібне узгодження адміністратора, а не сліпе повторення видачі.

Contact доставляє запрошення на ярмарки через фізичний зразок, резерв паперу та збережену чергу; [інструкція](CONTACT-FAIRS.md). Економіка не залежить від пошти. Відомий зв’язок акаунтів адміністратор реєструє командою `/market admin related РИНОК гравець1 гравець2 підстава`. Їхні угоди отримують позначку `FILL_REVIEW` у службовому журналі. Система не обіцяє автоматично виявляти альтернативні акаунти.

## Офіційний обмін

Міський керівник у FX вмикає `/market manage ID official true` і вносить міські кошти: `/market manage ID official_deposit KRN 1000.00`. Добровільний внесок **власних** коштів керівника: `official_contribute KRN 100.00`; він стає власністю міського фонду. Виведення `official_withdraw` повертає вільні кошти тільки міській казні.

`/market exchange official KRN SOL 10.00` спочатку показує вихід, збір, повне списання та місце видачі. Вихід обчислюється як `floor(input × (R_KRN/M_KRN) / (R_SOL/M_SOL))` у мінімальних одиницях. Курс приватної книги його не підміняє. За нульового R/M чи недостатнього вихідного залишку операція недоступна. У столиці емітента одна з валют має бути його власною; максимальна торговельна республіка допускає всі погоджені пари. Допуски міста й обох емітентів потрібні в обох випадках.

Фонд зберігає наявні монети окремо від золотого резерву. Обмін не друкує й не спалює монет, не змінює R/M. Особиста пільга договору застосовується до міського збору у валюті входу й витрачає відповідний валютний ліміт. Зміна оцінок, статусу, допусків або застосовної пільги потребує нового перегляду.

## Книги та двосторонні торгові договори

У нативному екрані «Моє» доступні створення васальної пропозиції, оформлення книги AUTO/MANUAL і системний перегляд. Політичні правила васалітету лишаються під `/t vassal`. Авторський текст не виконується й не підміняє вибрану данину.

Збережені `/t menu`, `/t army` та `/t treaty` працюють із відновленим кодом установленого 1.11. У конструкторі `/t treaty` обидві сторони спочатку погоджують редакцію; кнопка підпису відкриває `/t treaty view ID page`, після всіх сторінок доступний `/t treaty accept ID VERSION TOKEN`. Прямий виклик старого підпису без системного перегляду більше не приймається. Ці договори також перелічені у вкладці «Моє» нативного ринку.

Торгову чернетку створюють у JOBS:

```text
/market treaty create t:LEFT t:RIGHT OTHER_MARKET 0 50 50 1000.00 KRN 7 * 2026-11-10T12:00 2026-12-10T12:00 24
/market treaty book MANUAL ID авторський текст
/market treaty publish ID
/market treaty view ID 1
/market treaty accept ID VERSION PERSONAL_TOKEN
```

Поля після ринків: збори покупця/продавця/послуг у б.п., сума ліміту, валюта ліміту й пільгових операцій, період у добах, каталог точних специфікацій через кому або `*`, початок/кінець у Europe/Kyiv, повідомлення про припинення у годинах. Каталог обмежує товари; пільги послуг і FX перевіряють власну операцію та валюту. Чинні представники обох сторін і міст обох ринків мають погодити механічні умови. Кожна особа читає всі сторінки до появи персонального токена на 60 секунд. Чужий токен, стара версія або втрачені повноваження не приймаються.

`book` створює нову версію й скидає старі погодження. Для чинних умов `amend ID buyer seller jobs quota end` готує окрему поправку; вона не змінює активну версію до повного погодження. `reject ID` відхиляє пропозицію, `terminate ID` застосовує погоджене повідомлення. Активний договір належить містам/державам і переживає зміну правителя. Для ще не активованої згоди представник перевіряється повторно.

Звичайна пільгова заявка резервує весь ліміт наперед, має строк у межах пільги; виконання переводить резерв у витрачений оборот, скасування звільняє залишок. Утрата громадянства скасовує невиконаний залишок. Прийняті роботи й аукціонні ставки зберігають погоджену комісію. Найнижча застосовна ставка вибирається без складання знижок.

## Постійні міські закупівлі

Мер особисто в GOODS тримає точний зразок і відкриває форму «Керування → Постійна закупівля», або:

```text
/market procurement create KRN 500 2000 3.00 5000.00 1000.00 250 3
```

Це поріг запасу 500, ціль 2000, максимальна ціна 3.00, фонд 5000.00, граничні витрати зі зборами за ковзні 24 години 1000.00, до 250 предметів у новій заявці зі строком 3 доби. Джерело — міська казна, покупець і власник предметів — місто. Фонд не належить меру.

Раз на хвилину доручення враховує вільні предмети міста саме цього ринку та незаповнені власні замовлення. Кошти резервуються до публікації; вигідніша ціна та скасування повертають залишок у той самий фонд. Фактичні витрати й усі активні резерви входять до добового ліміту. Перезапуск не дублює потребу.

`list`, `view ID`, `pause ID`, `resume ID`, `stop ID`, `deposit ID amount`, `amend ID low target price daily batch` доступні у формах і командах. Пауза скасовує залишки; зупинка повертає вільний фонд місту. Недоступна будівля, брак коштів, відкликаний допуск або заповнене сховище показуються причиною очікування. Закриття ринку завершує доручення та повертає вільний фонд у казну.

## Аукціони

```text
/market auction create 10 KRN 10.00 1.00 100.00 24
/market auction create_asset CITY_ASSET_ID 10 KRN 10.00 1.00 100.00 24
/market auction bid ID 20.00
/market auction bid ID 20.00 e:t:CITY_ID
/market auction buyout ID
/market auction cancel ID
```

Перший варіант забирає точний лот із руки через постійну інвентарну передачу; до її підтвердження аукціон не відкритий. Другий атомарно резервує вільний предметний актив міста на цьому ринку й потребує права керувати його казною. Строки 1/24/72 години, до 5 активних лотів одного власника на ринку. Нульова ціна викупу означає його відсутність.

Ставка особисто біля GOODS резервує всю суму та погоджений збір. Підвищення власної найбільшої ставки списує тільки різницю; чужа більша ставка повертає попередній резерв у місцеве отримання. Власник коштів не купує власний лот, зокрема через іншого міського посадовця. Ставка, яка досягає викупу, потребує окремого підтвердження викупу саме за оголошеною ціною.

Ставка в останні 2 хвилини продовжує лот до 2 хвилин після неї, максимум на 30 хвилин від початкового кінця. Після першої ставки продавець не скасовує лот. Тариф продавця фіксується при публікації, тариф покупця — при його ставці. Для обмеженої пільги продавця з лімітом потрібен викуп: резервується максимальний можливий оборот. Без викупу застосовується звичайна ставка або пільга без обмеження обороту; ціна продажу не має відомої верхньої межі.

Призупинення або закриття блокує нові ставки. Прийнята найбільша ставка розраховується після спливу погодженого строку; без ставок закритий ринок повертає товар. Предмети й виручка надходять у місцеве отримання. Повторне завершення або перезапуск не створює другої виплати.

## Ярмарки, Contact і чат

Форми керування та `/market fair create` підтримують чернетку ярмарку з відділами, каталогом, датами й тарифами; `fair letter edit ID текст` зберігає власноруч написане запрошення з новою версією. Скасування підготовки листа й скасування події — різні дії.

`preview` видає справжню листівку Contact за 1 папір. Після її перегляду організатор тримає зразок у руці й окремо підтверджує `confirm`: списуються зразок і по 1 паперу на зафіксованого адресата. Після збереження інвентарю ярмарок публікується, а черга доставляє до 8 копій за секунду. Повні й вивантажені скриньки чекають; змінені адреси пропускаються. Квитанція поруч із вмістом Contact захищає від повторного доставлення після перезапуску. Докладні правила й повернення невикористаного паперу — у [CONTACT-FAIRS.md](CONTACT-FAIRS.md).

Towny-конфігурація вимикає town/nation/outpost spawn. Штатні позитивні spawn-права прибрані; Feudal додатково накладає негативні права й перехоплює командні маршрути та обидва Towny spawn events. Звичайний відроджувальний механізм після смерті не змінюється. Нетранспортні `outpost list/add/delete/rename` залишаються доступними за їхніми звичайними правами.

Підтвердження адресуються конкретному гравцю як компоненти з оригінальними `RUN_COMMAND`/`SUGGEST_COMMAND` і hover. Клієнтський міст зберігає клікабельність та показ особисто адресованих інтерактивних повідомлень у вибраній вкладці ChatPlus. Текст гравця не перетворюється на дію через схожість із командою.

## Збирання й приймання

Серверну частину перевірено на JDK 21 проти встановленого Mohist/Towny; цільовий байткод плагіна — Java 17. Повний JDK потрібен для `--release`, самого JRE недостатньо.

```bash
python3 feudal/build.py \
  --server-api server/libraries/net/minecraftforge/forge/1.20.1-47.4.23/forge-1.20.1-47.4.23-server.jar \
  --api-libraries server/libraries --output-dir work/market-release
cd bridge
bash gradlew test build --no-daemon
```

ForgeGradle використовує JDK 17 і справжній Forge 1.20.1-47.4.23 API, а також встановлений ChatPlus 2.8.1-empirecraft.2. Серверний API не підміняється набором саморобних класів Minecraft. Деталі автоматичних і ще не виконаних ігрових перевірок — у [звіті](../validation/city-markets-1.13.2.md).

Особиста пам’ять приватів у Bridge 1.8.1: [правила відкриття, збереження та перевірка](../bridge/MAP-HISTORY.md). Віддалені території зберігають останні спостережені назви й межі до повторного візиту.
