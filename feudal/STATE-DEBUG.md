# Команди для відлагодження розвитку держав

Доступ: оператор сервера або право `empirecraft.feudal.debug`. Саме право `empirecraft.feudal.admin`, посада мера чи короля доступу не дають. Для команд через Towny також потрібне звичайне `empirecraft.feudal.use` (типово доступне всім).

У грі: `/t state debug help` або `/t держава debug help`.
З консолі й у грі також доступна `/statedebug` з тими самими аргументами: наприклад, `statedebug next держава:Русь county`.

| Команда | Дія |
|---|---|
| `/t state debug info [володіння]` | Поточні статус, форма правління, устрій, ревізія та доступні наступні статуси. Без аргументу — власне володіння; у консолі аргумент обов’язковий. |
| `/t state debug next <володіння> [статус]` | Миттєво перейти на наступний рівень за чинним деревом розвитку, пропустивши населення, споруди, договори, голосування й очікування. Якщо напрямків кілька, команда покаже варіанти й попросить указати ціль. |
| `/t state debug setstage <володіння> <статус>` | Установити будь-який статус: перестрибнути рівні, понизити рівень або перейти в іншу гілку. |
| `/t state debug government <володіння> <форма>` | Примусово встановити форму правління без голосування та вимог; для республіки починається новий строк правління. |
| `/t state debug territory <володіння> <устрій>` | Установити територіальний устрій без голосування. |
| `/t state debug ready <володіння> <статус>` | Пропустити лише строк стабільності, якщо всі поточні вимоги вже виконано. Далі правитель подає й підтверджує звичайну заявку на підвищення. |

Володіння можна вказувати за ID (`n:UUID`, `t:UUID`), назвою або через `держава:Назва` / `місто:Назва`. У назвах із пробілами використовуйте `_`. Tab підказує ID, допустимі наступні статуси, форми правління та устрої. `help` показує синтаксис.

## Приклади

Для баронства, у якого є лише один наступний рівень:

```text
/t state debug next держава:Русь
```

Вибрати гілку з поселення або відразу перевірити імперію:

```text
/t state debug next держава:Русь barony
/t state debug setstage держава:Русь empire
/t state debug government держава:Русь republic
/t state debug territory держава:Русь direct
```

Перевірити звичайний перехід із поселення до племені без семи діб очікування (після виконання вимог):

```text
/t state debug ready держава:Русь tribe
/t state advance submit держава:Русь tribe
/t state advance confirm держава:Русь
```

Статуси: `settlement`, `barony`, `county`, `duchy`, `kingdom`, `empire`, `tribe`, `principality`, `horde`, `khanate`, `khaganate`, `central_state`, `central_kingdom`, `central_empire`, `free_city`, `trade_republic`.

Форми правління: `monarchy`, `tribal_council`, `republic`, `absolute_monarchy`, `sultanate`, `military_order`. Устрої: `feudal`, `direct`, `autonomous`, `federal`.

## Поведінка під час тестування

Кожна зміна зберігає автора, старе та нове значення в `/t state history <володіння>` і загальному журналі аудиту. Дані переживають перезапуск. Зміна статусу використовує ті самі ефекти, що й звичайне підвищення: плем’я отримує племінну раду, вольне місто й торговельна республіка — республіку з новим строком, `central_state` — прямий устрій. Решта осей зберігається; для їх зміни використовуйте `government` і `territory`.

Примусова зміна статусу, форми правління або устрою скидає старі заявки, строки готовності, відкриті політичні рішення й незавершені відкриті вибори. Вони залишаються в історії, але потребуватимуть нового створення. `ready` скидає стару заявку й залишає голосування чинними, оскільки не змінює устрій держави.

Команди змінюють політичні записи, а не Towny-привати, посади, фінанси чи васальні договори. Підвищений статус сам по собі не створює споруд і васалів та не виконує вимоги наступних звичайних підвищень. Для повернення до попередньої тестової конфігурації явно задайте попередні статус, форму та устрій.

Архівні й уже об’єднані володіння змінювати не можна. Якщо вибори вже підготували передачу влади (`PREPARED`), спершу її потрібно завершити або скасувати штатними `election resume` / `election abort`.

## Установлення та перевірка

Зібрати плагін і запустити всі тести: `python feudal/build.py` (JDK 17+, Python 3). Готовий файл: `server/plugins/empirecraft-feudal-1.6.0.jar`. Зупиніть сервер, замініть наявний JAR і запустіть сервер знову. Наявний файл конфігурації й базу даних залиште на місці.

Новий набір `PoliticsDebugTests` перевіряє права, розгалуження, ефекти підвищення, відсутність змін грошей і земель, очищення старих заявок, строк стабільності, захист підготовлених виборів, збереження після перезапуску та маршрутизацію української команди Towny. Повний запуск Mohist із клієнтом Minecraft не входить до цих автоматичних перевірок.
