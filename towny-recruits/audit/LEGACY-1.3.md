# Аналіз наданого TownyRecruitsBridge 1.3

Вхідний файл: `TownyRecruitsBridge-1.3.jar`, 18 420 байтів.
SHA-256: `e941017b65f7d2e7aebcd7073da8686a3972f79b17c23712e1dc98abeffb8d2b`.

Це **Bukkit-плагін** (`plugin.yml`, `extends JavaPlugin`), а не Forge-мод. Новий
`TownyRecruits.jar` — Forge-мод; він не містить і не запускає старий JavaPlugin.

Досліджені всі шість класів: `TownyRecruitsBridge`, `TownyReader`, `RecruitsGateway`,
`Reconciler`, `Reconciler$Nation`, `Reconciler$Recruits`; також `plugin.yml` і `config.yml`.
Декомпіляція CFR 0.152 звірена з фактичними сигнатурами Villager Recruits 1.15.0.

| Фактична можливість 1.3 | Перенесення в 2.0 |
| --- | --- |
| `tn_` + перші 8 символів UUID нації | Наявний ID зберігається; нові ID використовують повний UUID |
| `adopt-existing-factions`, збіг назви або короля | Автоматичне підхоплення, постійний UUID → ID; неоднозначні збіги блокують міграцію |
| Створення/видалення фракцій та scoreboard-команд | Єдина синхронізація з Towny; видалення також для підхоплених ручних фракцій |
| Додавання/виведення онлайн-учасників | Розширено на офлайн-учасників і необмежену кількість гравців |
| Ворожнеча/альянс/нейтралітет, пріоритет війни | Збережено симетричні правила; очищаються також дипломатія та договори видалених фракцій |
| `/trbridge status`, `limit`, `limit list`; `trbridge.admin` | Збережені команди, консоль та право; одна система лімітів |
| `get/setMaxNPCs`, `get/setMaxNPCsPerPlayer` | Перший запуск читає чинні значення з самої Recruits-фракції |
| Особливий ліміт короля | Король користується спільним лімітом, інші учасники — індивідуальним у межах спільного |
| Native `0` у загальному ліміті означає «необмежено» | Збережено для старих фракцій і `/trbridge limit ... 0 ...`; `/townyrecruits setlimit ... 0` вимикає найм |
| `dry-run`, інтервал синхронізації | `sync.dry-run`, інтервал 20–40 тіків у новій конфігурації |
| Збереження через RecruitsFactionManager | Старі файли не скидаються; новий журнал імпортує ліміти один раз |

У 1.3 **немає** власної бази лімітів, GUI найму, розвитку, обліку походження рекрутів,
прив’язки до `/t provision`, або окремого коду власності NPC. Останнє реалізовував
оригінальний Villager Recruits. Тому вигаданий імпортер відсутнього формату не додається.

Наданий конфіг усередині JAR — це шаблон (`dry-run: true`, інтервал 10 секунд,
`adopt-existing-factions: true`). Окремий робочий конфіг користувач не надав. Нові значення
за замовчуванням відповідають ТЗ, зокрема реальна синхронізація і 15/15 **для нових** націй.
Зовнішній старий конфіг, якщо він є на сервері, копіюється до резервної папки.

Крім старого мосту збережено клієнтський рендер, 128 скінів, зріст, бойові накази,
мушкети, полки та контракти вже наявного проєкту 1.5.0. Незмінені класи беруться
з перевіреного власного 1.5 JAR, а не замінюються спрощеними реалізаціями.
