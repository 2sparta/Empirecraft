# Фактичні перевірки TownyRecruits 2.0.0

Готовий JAR: **672 117 байти**, SHA-256
`3c2f7f3651de06156f61088c6fe4109a98e847b8da88547397d0ede068c0b276`.
Саме ці байти завантажувалися в обох успішних фазах перевірки.

- Java 17: компіляція змінених спільних/серверних класів проти справжніх встановлених
  класів Minecraft, Forge, Bukkit, Recruits та залежностей. Підмін API в JAR немає.
- **19 перевірок журналу та команд**: десяткові значення без похибки, недопустимі числа,
  відмова від’ємного залишку, 100 одночасних запитів резервування, повторне відкриття
  файлу, ідемпотентне повернення, помилка диска без списання розвитку та `.bak`.
  Українські й узяті в лапки назви розбираються без зависання.
- **38 перевірок у першому запуску** справжнього Mohist 71a84ff7 / Forge 47.4.23,
  Minecraft 1.20.1, Java 21. Towny 0.101.2.0, Villager Recruits 1.15.0,
  Musket 1.5.4, завантажений Boomsticks, Supplementaries, Moonlight, GeckoLib, NoEnd.
  Для меню та складу використано наявний локальний EmpirecraftFeudal **1.11.0** з H2.
- **9 перевірок другого запуску** того самого світу: серіалізовані дані Towny/Recruits,
  обидва живі NPC, розвиток 8.5, відкриті щитоносці, ліміти 3/2 та старі 77/12,
  100 учасників, а потім штатне видалення нації й фракції.
- Структура JAR: Forge-дескриптор 2.0.0, відсутність `plugin.yml` та чужих класів API,
  128 скінів; **61 клієнтський/тактичний клас** байт у байт збігається з 1.5.0.

У першій фазі перевірено живі `RecruitEntity` і `RecruitShieldmanEntity`, їхню фракцію,
місце появи, оплату 5/10 злитків і 0.5/1 розвитку, недоступний тип, права, недостатні
ресурси, заповнений ліміт, загибель і звільнення слота. Штатну подію створення NPC
навмисно скасовано: золото, розвиток і слот повернулися. Успішний тест містить
очікуваний запис `Створення рекрута скасовано` саме для цього сценарію.

Перевірено кнопки в справжньому меню Feudal/Towny та відкриття інвентарного GUI найму.
Штатний `TownStatusScreenEvent` зберіг початковий рядок і додав розвиток та армію.
Гравець — офіційний Forge FakePlayer, а 100 учасників — справжні записи Resident Towny.
Офлайн-вступ і вихід змінювали розмір фракції 100 → 99 → 100.

Провізія перевірялася через справжні `ProvisionController`, `ArmyService`, H2-склад,
`army_food_receipts` та `army_units.feed_total`. Голод зростав на оплачені 10 одиниць,
чужий запас залишився незмінним. Навіть зовнішня зміна `army_units.home` не змінила
місто походження під час наступного харчування. Native `canEatItemStack` для
найнятого рекрута відхиляє їжу з інвентарю.

Окремо пройшов чинний `ArmyDataTest` зі справжнім NBT: збереження лічильника
без завантажених NPC, вихід гравця, видалення нації, стиснені entity-регіони,
нульовий файл регіону, відмова пошкодженого заголовка, атомарний збій і повторна індексація.

## Ізоляція тесту та межі результату

Використовувався тільки тимчасовий світ у `build/native-test`; робочий світ сервера
не запускався. Окремий тестовий Forge-мод не входить до готового JAR.
Фонові політичні перетворення Feudal призупинялися у тесті, щоб він не замінював
створені напряму тестові нації власними державами. Для другого запуску його JAR
прибрано лише з тестового сервера: ця фаза ізольовано перевіряє Towny/Recruits.
Перша фаза із чинним Feudal перевіряє меню й фактичне списання провізії.

Код інтеграції провізії та її схема звірені також із джерелами Feudal **1.18.0** у
`main`. Сам його готовий великий JAR не вдалося отримати через поточний GitHub-конектор;
живий запуск Feudal 1.18.0 і всього виробничого модпака **не позначається перевіреним**.
Підтверджені тести не означають 100 одночасно підключених клієнтів.

Під час запису на Windows не відкривається дескриптор папки, якого Java там не підтримує;
файл примусово зберігається та атомарно замінюється. Сам Windows-сервер тут не запускався.

Не виконувалися: графічний запуск повного клієнта, навантажувальний TPS/FPS-тест,
перевірка всіх можливих моментів `kill -9`/аварії живлення, ручний розбір неоднозначної
операції після стороннього редагування інвентарю. Для такого випадку є стійкий журнал,
резервування та адміністративне `recover`; успішна автоматична перевірка не вигадується.

Попередня помилка тестового перезапуску була падінням NPC із точки Y=65 над низькою
поверхнею superflat. У виправленій перевірці під точкою є твердий майданчик; ті самі
збережені NPC пережили перезапуск. Це виправлення тестового середовища.

## Відтворення

```text
python3 build_unified.py --server-home /path/to/server
python3 test_ledger.py --gson /path/to/server/libraries/com/google/code/gson/gson/2.10/gson-2.10.jar
python3 smoke_unified.py --reset-world --server-home /path/to/server --java /path/to/java
```

Для іншого готового Feudal/Boomsticks можна вказати `--feudal` і `--boomsticks`.
Тестовий запуск використовує localhost:25595. Вихідні маркери успішних перевірок:
[`audit/native-checks.txt`](audit/native-checks.txt).
