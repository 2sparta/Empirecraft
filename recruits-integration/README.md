# Рекрути, Towny та Feudal — інтеграція 1.0.0

Серверний додаток для наданого `recruits-1.20.1-1.15.0.jar`, Towny 0.101.2.0 та Mohist/Forge 1.20.1 (Forge 47.4.23). Пакет містить Feudal **1.11.0**, TownyRecruitsBridge **2.0.0** та серверний мод **empirecraft-recruits-integration 1.0.0**. Клієнти зберігають оригінальний Recruits 1.15.0. Для наявної збірки Towny потрібна **Java 21**.

## Встановлення

1. Зупинити сервер і зробити резервну копію його світу, даних Towny та `plugins/EmpirecraftFeudal`.
2. Замінити попередній Feudal і `TownyRecruitsBridge-1.0.jar` файлами з каталогу `server/plugins` у пакеті. Одночасно має бути встановлена лише одна версія кожного плагіна.
3. Додати `empirecraft-recruits-integration-1.0.0.jar` у `server/mods`. Оригінальний Recruits 1.15.0 залишається встановленим. Додатковий мод клієнтам не потрібен.
4. Запустити сервер. Повідомлення мосту «Recruits ↔ Towny/Feudal підключено» підтверджує підключення. Перевірити `/t menu` → **Рекрути**.

Дані попередніх договорів зберігаються. Нові таблиці армії додаються до тієї самої бази Feudal. Старий `dry-run` мосту 1.0 більше не використовується: версія 2.0 працює через Feudal. Сторонні фракції та старі записи `tn_*` автоматично не видаляються. Нові керовані фракції мають стабільні ідентифікатори `ec_*`, прив’язані до UUID володіння.

## Дипломатія та бої

- Рекрути не завдають шкоди своєму командиру, громадянам власного володіння, членам тієї самої держави, сюзерену, васалам одного васального дому та прямим союзникам. Враховуються взаємні союзи Towny, союзи Feudal і договори про ненапад. Союзники союзників не стають союзниками автоматично.
- Нейтральних гравців і рекрутів не атакують першими. Формальна війна задається через `/army war`; випадковий удар не оголошує війну. Самооборона проти конкретного нападника діє 120 секунд, якщо вона не суперечить союзу або ненападу.
- Враховуються PvP світу й Towny, включно з ділянками. Мирні жителі й тварини захищені; боротьба з ворожими мобами залишається доступною.
- Перевіряються вибір цілі, ближня атака та влучання снарядів. Стріли зберігають походження і після вивантаження або загибелі стрільця. Заборонена ціль скидається також у вже виданому наказі.
- Нативне автоматичне оголошення ворожнечі Recruits за значну шкоду вимкнене для керованих загонів. Клієнтські UUID не заміняють справжнього відправника команди; керовані фракції не можна редагувати через нативні меню Recruits.
- Якщо зв’язок із Feudal або актуальні дані дипломатії недоступні, керовані рекрути припиняють такі бойові дії до відновлення зв’язку.

## Міська провізія та голод

Усі найняті рекрути харчуються з провізії міста власника, **без витрачання їжі зі свого інвентарю чи приватних скринь утримання**. Для гарнізону джерело призначається окремо: власне або прямо адміністроване місто. Скарби чи провізія довільного васала не вилучаються.

Запас спільний із `/t provision`; також додано псевдонім `/t provishion`. Залишки поживності від цілих предметів зберігаються в обліку. Повтор квитанції після збою не списує порцію вдруге. Незавершена передача предметів не використовується для харчування, доки її журнал не узгоджено.

Типова витрата — **2 пункти голоду за реальну хвилину**. Одна одиниця поживності відновлює 5 пунктів голоду. При голоді ≤50 рекрут намагається отримати до 10 одиниць поживності; доступна менша порція теж використовується. За безперервної активності це приблизно **576 одиниць поживності на рекрута за реальну добу**. Точна кількість предметів залежить від їхньої поживності в системі міста.

Коли запас вичерпано, голод поступово падає. При нульовому голоді рекрут втрачає **1 HP кожні 10 секунд** і може загинути, навіть маючи їжу в інвентарі. Рекруту потрібне чинне місто постачання. Збій календаря або недоступність обліку призупиняє харчування й голод, а справжня відсутність запасу спричиняє голодування.

Харчуються лише завантажені живі рекрути. Час вивантажених чанків не нараховується; після затримки сервера разове наздоганяння обмежено хвилиною. Зміна системного часу назад не збільшує голод.

Необов’язкові параметри у `plugins/EmpirecraftFeudal/config.yml` (застосовуються після перезапуску):

```yaml
army:
  hunger-per-minute: 2.0
  starve-every-seconds: 10
```

## Вкладка «Рекрути»

У `/t menu` додана кнопка з шоломом; прямий доступ — `/army menu [володіння]` або `/t army menu [володіння]`.

Показуються відомі живі рекрути, завантажені та голодуючі, UUID і власник кожного, належність гарнізону, місто постачання, голод, спільний запас міста, фактичні витрати за 24 години, прогноз добових витрат, ставка утримання та рішення ради. Є історія подій і сторінки списку. Перегляд доступний громадянам, правителю та адміністратору.

Старі рекрути реєструються при першому завантаженні їхніх чанків. Загальна кількість означає **відомих системі** рекрутів; мод не завантажує весь світ для перепису.

## Гарнізони, командування та утримання

Особисті рекрути залишаються особистими. Правитель може добровільно передати **лише власного** завантаженого рекрута володінню. Гарнізон підпорядковується посаді: при зміні мера/монарха командування отримує новий правитель. Старий правитель втрачає ці права. Воєначальниками можна призначити громадян володіння. Повернення з гарнізону віддає рекрута первісному власнику; для архівного володіння таке повернення може виконати сам первісний власник.

| Команда | Дія |
| --- | --- |
| `/army assign UUID володіння місто` | Передати власного рекрута в гарнізон |
| `/army supply володіння місто` | Змінити місто постачання гарнізону |
| `/army release UUID` | Повернути рекрута первісному власнику |
| `/army officer володіння гравець` | Призначити воєначальника |
| `/army revoke володіння гравець` | Відкликати повноваження |
| `/army command володіння follow` | Слідувати за уповноваженим командиром |
| `/army command володіння hold` | Зупинитися |
| `/army command володіння defend` | Обороняти позицію |
| `/army command володіння attack UUID` | Атакувати дозволену ціль |
| `/army upkeep володіння сума валюта ліміт` | Встановити добову ставку на одного гарнізонного рекрута і ліміт |
| `/army history володіння [сторінка]` | Переглянути списання, смерть, передачі та зміни |
| `/army why UUID_рекрута UUID_цілі` | Пояснити дозволену або заборонену атаку свого загону |
| `/army inspect UUID` | Адміністративна діагностика обліку |

Групові накази отримують лише уповноважені завантажені гарнізонні рекрути в тому самому вимірі, у межах 128 блоків. Нативні дозволені команди також перевіряють реального відправника. Для приватного перепризначення, розпуску, підвищення до компаньйона або запису в яйце гарнізон спочатку потрібно повернути власнику через `release`.

Типова ставка — **0**, ліміт — **200**. Нативні обмеження Recruits також залишаються чинними. Найм вимагає громадянства міста й вільного місця за міським лімітом. Утримання гарнізону оплачує скарбниця володіння за реальні доби, включно з вивантаженими загонами. Кошти надходять на службовий рахунок утримання; вони не виплачуються командиру. Раніше нараховані борги не зникають після загибелі/повернення рекрута або зміни ставки. Після двох діб несплати гарнізон отримує сповільнення; автоматичного зникнення рекрутів за борг немає. Особисте нативне грошове утримання Recruits зберігається, якщо адміністратор його ввімкнув; міська система заміняє його саме для гарнізону.

## Війни, рада та договори

- `/army war ваше_володіння інше_володіння` — оголосити формальну війну. Потрібен чинний правитель; союзи, ненапад, власна держава та васальні зв’язки перешкоджають оголошенню. Дотримуються права автономії васального договору.
- `/army wars` — перелік активних війн із UUID.
- `/army peace ваше_володіння UUID_війни` — погодити мир; потрібне погодження обох чинних правителів.
- `/army vote UUID_рішення yes|no` — голосування. Республіка й племінна рада схвалюють війни, мир і політику утримання більшістю чинного складу. Зміна складу чи повноважень потребує нового рішення; строк голосування — дві доби.

У війнах цього реєстру враховуються військові обов’язки підписаних васальних договорів: лише оборонні війни, усі війни або відсутність обов’язку. Обов’язок сюзерена захищати васала додає його до оборонної сторони. Оголошення від імені держави охоплює її міста; окремий мер не мобілізує всю державу.

Це визначає бойові відносини загонів. Марші, перевезення, військові внески грошима/спорядженням і додаткові рольові положення виконуються гравцями. Додаток не переміщує армії автоматично й не підміняє сторонній плагін облоги або захоплення територій. Захист будівель залишається у Towny/ClaimGuard. Війни сторонніх плагінів потребують окремої інтеграції; нативний прапорець ENEMY Recruits сам по собі не є оголошенням війни для цієї системи.

## Відтворення збірки та перевірок

Використовуються бібліотеки з цього репозиторію; початкові JAR не змінюються. SHA-256 оригінального Recruits перевіряється при збірці. Потрібні Python 3 і JDK-компілятор 17 або новіший; `JAVA_HOME` задає компілятор.

```sh
python3 feudal/build.py
python3 recruits-integration/build.py
python3 recruits-integration/mixin_test.py
python3 recruits-integration/package.py
```

Feudal перевіряє реальну H2: провізію, повтор квитанції, часткові порції, права, спадкування командування, борги, раду, війни та збереження після відкриття бази. Перевірки голоду використовують детермінований час. Mixin-перевірка застосовує справжні перехоплення до 94 класів і перевіряє байткод ASM, зокрема сумісне накладання з ProjectileOwnerMixin встановленого ClaimGuard.

Окремий тест `tests/smoke/ArmySmokePlugin.java` працює на справжніх Mohist, Towny та Recruits у новому тимчасовому світі, створює тестові міста й рекрутів, перевіряє провізію, особисту їжу, повтор старої квитанції після кількох порцій, паузу при недоступному календарі, васальні відносини, цілі, походження стріл і смерть без провізії, а потім завершує сервер. Цей тестовий плагін не входить до пакета встановлення. Для підготовки одноразового сервера: `python3 recruits-integration/smoke_test.py`; виконувати лише команду запуску, яку він виведе, у створеному ним каталозі. Візуальне відображення меню окремо перевіряється ігровим клієнтом.

Перевірено в цьому середовищі: 90 перевірок армії на H2, 110 перевірок голоду, 144 перевірки договорів і наявні регресійні набори Feudal; 94 класи / 1253 методи у Mixin-перевірці з ClaimGuard; 23 перевірки на одноразовому справжньому сервері. Візуальну перевірку меню з клієнта Minecraft не виконано.
