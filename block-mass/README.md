# Маса модових блоків — 1.0.0

Порожній список `blocks` у Ship Physics залишав багато модових блоків з автоматичною щільністю 1000 кг/м³. Наприклад, велика шестірня Create на скриншоті важила 355,5 кг і показувала «Автоматична оцінка».

Це оновлення задає матеріали через 48 окремих тегів `empirecraft_mass`. У каталозі 12 968 унікальні ідентифікатори з ресурсів установлених модів: Create, Create Big Cannons, Chipped/Chipped Extras, Handcrafted / Timber & Joinery, Dawn of Time, Supplementaries, фермерські моди та інші. Це кількість ідентифікаторів ресурсів, а не виміряна кількість зареєстрованих блоків у запущеному світі. Частина JAR зберігає ресурси вимкнених реєстрацій; для них використовуються необов’язкові точні ID. Теги не реєструють блоків і не повертають вилучений контент.

## Баланс

Маса = ефективна щільність × об’єм форми, який обчислює поточний Ship Physics. Для порожнистих предметів і змішаних механізмів щільність означає масу всієї конструкції на одиницю її форми, а не щільність суцільного металу. Значення є балансом збірки; вони не виведені з фізичного зважування моделей.

| Конструкція | Щільність, кг/м³ |
| --- | ---: |
| Звичайна деревина | 500 |
| Дерев’яні шестірні з кріпленнями | 650 |
| Андезитовий вал / суцільний сплав | 2600 |
| Андезитовий механізм у корпусі | 1500 |
| Порожнистий латунний / мідний механізм | 1800 / 1400 |
| Листовий метал / порожниста металева конструкція | 1200 |
| Дерев’яні меблі / порожня дерев’яна тара | 200 / 180 |
| М’які меблі / полотно | 120 / 140 |
| Наповнена бочка / ящик із продуктами | 1000 / 450 |
| Камінь / кераміка | 2500 / 1900 |
| Суцільне залізо / сталь / бронза | 7870 / 7850 / 8800 |

Для того самого об’єму, що на скриншоті, велика шестірня матиме приблизно **231,1 кг** замість 355,5 кг. Інший стан або форма може давати інший об’єм. Написи нових матеріалів перекладені українською, англійською та російською.

Окремо перевірені неоднозначні назви: гарматні `barrel` залишаються металевими стволами; `tin_ore` є рудою в камені; `stone_grass_topped_wall` залишається каменем; `brick_bond_oak_planks` і дерев’яна мозаїка залишаються деревом. Суцільні металеві блоки відрізняються від порожнистих корпусів.

Copycats та Create Copycat продовжують отримувати матеріал вставки і фактичний об’єм частин. Блоки Sails, буї, баласт і блоки Valkyrien Skies зберігають власну масу. Vanilla-блоки, глобальні параметри ударів, плавучості й керування не перевизначаються. Форма, стани плит/сходів і перерахунок інерції залишаються в наявному моді фізики.

## Встановлення

Пакет `dist/Empirecraft-Block-Mass-1.0.0.zip` містить лише конфігурацію, дані та переклади.

1. Зупиніть сервер і клієнт. Скопіюйте `server/config` та `server/kubejs` у відповідні папки сервера зі злиттям папок. На клієнт скопіюйте кореневі `config` та `kubejs`.
2. Залиште встановлені `empirecraft-ship-physics-1.2.0.jar`, KubeJS та решту модів поточної збірки. Замінювати JAR-файли чи оновлювати список ADM не потрібно.
3. Запустіть сервер і клієнт заново. Після входу теги та конфіг передаються клієнту. Shift над блоком або `/shipphysics inspect` показує матеріал і масу. Для великої шестірні має бути «Дерев’яний механізм з кріпленнями» без повідомлення про автоматичну оцінку.

Повний перезапуск потрібен для узгодженого завантаження тегів і фізичних матеріалів. Наявні кораблі перераховує стандартний механізм `MassSync` під час завантаження. Якщо конфіг сервера змінювали вручну, перенесіть нові `materials`, `surfaces` і `blocks`, зберігаючи власні решту параметрів. Вміст звичайних скринь та інвентарів цим оновленням не зважується; «напoвнена бочка» тут означає конкретний блок із такою конструкцією, а не читання його інвентарю.

## Відтворення та перевірки

- `catalog.json` — явне призначення матеріалу кожному ID. У runtime немає нового вгадування за назвою.
- `profiles.json` — щільність, міцність, базова поверхня та переклади додаткових матеріалів.
- `settings-base.json` — вихідна конфігурація; генератор зберігає її наявні матеріали й глобальні параметри.
- `inputs.json` — SHA-256 46 JAR із ресурсами блоків; `exclusions.json` пояснює пропуски.
- `python block-mass/build.py` генерує парні клієнтські/серверні файли; `--check` перевіряє їх актуальність.
- `python block-mass/test.py --scan --runtime` звіряє всі ресурси з JAR, перевіряє семантичні випадки й виконує справжній `PhysicsConfig.class` із встановленого мода. У тесті парсера замінені лише перевірка ResourceLocation і очищення кешу; Forge, світ і мережа не запускаються.
- `python block-mass/package.py --check` перевіряє відтворюваність готового ZIP.

Автоматичні перевірки пройдено. Запуск повного Mohist-світу, екранні підказки й поведінку кораблів після зміни маси потрібно перевірити в грі; їх тут не заявлено як перевірені.
