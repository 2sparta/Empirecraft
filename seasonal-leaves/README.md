# Empirecraft Seasonal Leaves 1.2.2

Серверний мод для **Minecraft 1.20.1 / Forge 47.x**. Потрібні Serene Seasons 9.1.0.3 і GlitchCore 0.0.1.1. Клієнтам цей мод установлювати не потрібно.

Версія 1.2.2 додає постійний адміністративний перемикач росту всередині моду 1.2.1, наданого власником. Збережено поступове опадання/відновлення крони, швидке сезонне прибирання, повільну появу рослин і контроль природних саджанців із 1.2.1. Початковий JAR має SHA-256 `ac3c5516e098a5b46d1fa61dd990ac5ed4e992ca8f3388c4ef07226a5f2610cd`.

## Команди адміністратора

| Команда | Дія |
| --- | --- |
| `/plantgrowth off` | Повністю зупинити ріст і появу рослин, якими керує мод |
| `/plantgrowth on` | Дозволити ріст з урахуванням сезонів і попередніх обмежень |
| `/plantgrowth status` | Перевірити поточний стан |

Усі варіанти доступні лише джерелу команди з рівнем дозволу **2 або вище**: OP-гравцю з відповідним рівнем або серверній консолі. Звичайний гравець не може їх виконувати. У консолі команди вводяться без `/`. Стандартна команда `/op` залишається командою видачі прав оператора.

Підтвердження надходить адміністратору, який виконав команду:

- `Ріст рослин успішно вимкнено`
- `Ріст рослин успішно увімкнено`

Налаштування відразу зберігається в `config/empirecraft_seasonal_leaves-common.toml` і діє в усіх вимірах. За замовчуванням ріст увімкнений. Після перезапуску останній вибір зберігається. Для ручної зміни на зупиненому сервері:

```toml
[vegetation]
growthEnabled = false
```

Додайте ключ до **наявного** розділу `[vegetation]`; не створюйте другий такий розділ. Не плутайте `growthEnabled` із попередніми параметрами `enabled`: вимкнення сезонної обробки має іншу логіку й може відновлювати приховану рослинність.

## Що зупиняється

Вимкнений ріст блокує нову появу трави/квітів, повернення рослин із банку насіння, весняне відновлення листя, спроби природного відновлення рослин і дерев World Rules, випадковий ріст керованих рослин та ріст від кісткового борошна. Природні саджанці, відстежені модом, також не ростуть, зокрема через прямий виклик `SaplingBlock.advanceTree`.

Наявні рослини не видаляються командою. Сезонне прибирання та опадання листя продовжуються; записи прихованих рослин/крон зберігаються для наступного `/plantgrowth on`. Відновлення після ввімкнення поступове й підпорядковане сезону, біому, Towny та лімітам моду.

Область дії — рослини з каталогу моду, його листя та відстежені природні дерева. Автоматичний каталог охоплює наземні `BushBlock`; звичайні культурні `CropBlock`, невідстежені саджанці, азалії й горщики виключені, якщо їх не додано явно. Звичайні фермерські культури продовжують рости. Це налаштування не забороняє адміністративні `/setblock` та початкову генерацію нового ландшафту.

Додаткові datapack-теги: `empirecraft_seasonal_leaves:additional_vegetation`, `evergreen_vegetation`, `additional_leaves`, `additional_logs`, `evergreen`. Водонаповнені блоки та block entity зберігають попередні винятки.

## Установлення

Готові файли — у `dist/1.2.2/`:

- `empirecraft-seasonal-leaves-1.2.2.jar` — готовий мод;
- `Empirecraft-Seasonal-Leaves-1.2.2-install.zip` — мод, контрольна сума та інструкція;
- `empirecraft-seasonal-leaves-1.2.2-source.zip` — повний проєкт із Gradle Wrapper, вихідним кодом і перевірками.

1. Зупиніть сервер. Збережіть резервну копію світу та конфігу.
2. Приберіть попередній `empirecraft-seasonal-leaves-*.jar` із `mods/` і покладіть туди **один** JAR 1.2.2. Не видаляйте дані світу або попередній конфіг.
3. Повністю запустіть сервер. Новий параметр додасться автоматично зі значенням `true`.
4. Виконайте `/plantgrowth off` від OP-гравця або `plantgrowth off` у консолі.

Serene Seasons/GlitchCore не вкладені в JAR. Інтеграція World Rules необов'язкова, сумісний діапазон — `[1.0.2,1.0.3)`. Збережено попереднє `vegetation.requireWilderness=true`: для природних змін потрібна чинна перевірка Towny з World Rules; без неї ці зміни чекають. Для сервера без Towny адміністратор може окремо налаштувати `requireWilderness=false`.

## Збирання проєкту

Потрібні JDK 17 і доступ до Maven Forge/Mojang. Скопіюйте до `libs/` два оригінальні JAR за назвами й SHA-256 із `build-inputs.json`, тоді:

```sh
./gradlew build
# Windows: gradlew.bat build
```

Результат — `build/libs/empirecraft-seasonal-leaves-1.2.2.jar`. Wrapper використовує Gradle 8.8 із перевіркою офіційної SHA-256 дистрибутива. Залежності не пакуються в результат. У цьому середовищі готовий JAR зібрано й перевірено через наведений нижче офлайн-процес; Gradle-збирання не запускалося через недоступність Maven Forge/Mojang.

Для встановленого серверного toolchain Mohist 1.20.1 / Forge 47.4.23 також є повне збирання з тих самих вихідних файлів без завантажень. Потрібні Python 3.10+, JDK 17, установлені `libraries/` і залежності в `mods/`:

```sh
python3 build.py --server-home /path/to/server
python3 test.py
python3 mixin_test.py --server-home /path/to/server
python3 build.py --server-home /path/to/server --prepare-fixture
# Для наявного Mohist runtime тестовий процес запускається Java 21:
python3 growth_smoke.py --server-home /path/to/server
python3 package.py
```

`mixin_test.py` застосовує разом справжні Mixins Calendar/World Rules і цього моду та перевіряє перетворений байткод. `growth_smoke.py` запускає **тимчасовий** світ двічі: перевіряє права рівня 0/2, повідомлення, усі шляхи блокування росту, відновлення після ввімкнення й збереження `false` після повного перезапуску. Тестовий мод створюється тільки в `build/` і не входить до публікації. Перевірки природної появи використовують установлені World Rules, Calendar, CombatLog і Empirecraft No End. Точні результати наведені у `dist/1.2.2/validation.json`.

`smoke.py`, `prepare_runtime.py`, `toolchain.py` та старі сценарії у репозиторії залишені як історичні інструменти 1.1.0; поточний процес використовує команди вище. Попередні випуски у `dist/` не змінені.
