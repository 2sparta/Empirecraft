# Сезонне листя для Empirecraft

Серверне доповнення для Forge 47.4.23 / Minecraft 1.20.1 і Serene Seasons 9.1.0.3.
Клієнтам додатковий мод не потрібний: використовуються оригінальні блоки й звичайні оновлення світу.

- Восени частка голої крони плавно зростає від 0 до 100% за три підсезони.
- Усю зиму крони голі. Навесні листя поступово повертається; до літа крони повні.
- Використовується фактичний календар Serene Seasons, включно з прискоренням часу, командами та календарем Empirecraft. Віддалені чанки наздоганяють сезон після завантаження.
- Початкові blockstate, координати та опорна колода зберігаються разом із чанком у кореневому NBT `empirecraft_seasonal_leaves_v1`. Це працює для вже створеної мапи без нової генерації. Запис резервної копії й зміна блоків потрапляють в одне збереження чанка.
- Навесні відновлюються лише повітря або тонкий сніг. Інші блоки не перезаписуються. Зламана опорна колода скасовує відповідне відновлення; розміщення блока гравцем також скасовує запис у цьому місці.
- Листя без з'єднання з колодою пропускається. Пошук обмежений 12 кроками й 512 позиціями; незвично великі або нестандартні крони можуть частково залишатися зеленими.
- Сезони діють у вимірах із білого списку Serene Seasons (`overworld`, `world_europe` у цій збірці). Тропічні біоми Serene Seasons не оголюються. Області за world border, включно з віддаленим shipyard VS, не обробляються.
- Немає предметного дропу від сезонного опадання, повторних саджанців або сутностей листя. Водонаповнене листя й блоки з block entity пропускаються.

## Установлення

Готовий архів: `seasonal-leaves/dist/Empirecraft-Seasonal-Leaves-1.1.0.zip`.

1. Зупинити сервер і скопіювати `server/mods/empirecraft-seasonal-leaves-1.1.0.jar` у його `mods/`.
2. Додати конфіг `server/config/empirecraft_seasonal_leaves-common.toml` і повністю перезапустити сервер.
3. Зміни відбуваються поступово в завантажених чанках; `/reload` не встановлює JAR.

Для імпортованої карти конфіг у цьому репозиторії має `includePersistentLeaves=true`: деякі редактори мап позначають листя дерев як persistent. Такі блоки неможливо надійно відрізнити від поставлених гравцем; декорації з листя поруч із колодами також можуть змінюватися за сезонами. Якщо дерева карти мають звичайне природне листя, можна встановити `false` (це початкове значення самого моду).

Перед видаленням доповнення встановити `enabled=false`, залишити його працювати до відновлення потрібних завантажених територій, відвідати інші оголені території й зберегти світ. Видалення JAR посеред зими залишить прибрані крони голими, доки доповнення не повернуть.

## Дерева інших модів

Автоматично підтримуються блоки з тегами `minecraft:leaves` і `minecraft:logs`, незалежно від namespace. Оригінальний тип листя та всі властивості, включно з модовими, відновлюються без заміни на дубові.

Для модів без стандартних тегів додайте datapack-теги (pack format 15):

- `data/empirecraft_seasonal_leaves/tags/blocks/additional_leaves.json`
- `data/empirecraft_seasonal_leaves/tags/blocks/additional_logs.json`
- `data/empirecraft_seasonal_leaves/tags/blocks/evergreen.json` — винятки, які не повинні оголюватися.

Приклад: `{"replace":false,"values":[{"id":"anothermod:maple_leaves","required":false}]}`.
Спеціалізовані дерева без звичайних блоків листя/колод потребують окремої інтеграції. Фруктові block entity не видаляються.

## Навантаження та перевірки

За замовчуванням на вимір за тік: до 4096 перевірених позицій, 8 спроб роботи з листям, повторний прохід через 1200 тіків. Сусідні чанки примусово не завантажуються. Ліміт — 32768 збережених блоків листя на чанк; надлишок залишається на дереві. Не змінюйте NBT резервних записів вручну.

Збирання використовує ізольований named/SRG toolchain із `toolchain.py`, checksum-pinned входи `sails/build-inputs.json` і `build-inputs.json`, Java 17, Python 3.10+. Встановлені бібліотеки Forge повинні бути в `server/libraries`, оригінальні Serene Seasons/GlitchCore — в `server/mods`. Кеш можна передати змінною `EMPIRECRAFT_TOOLCHAIN`.

```sh
python seasonal-leaves/test.py
python seasonal-leaves/build.py --server-home server
python seasonal-leaves/build.py --prepare-fixture --server-home server
python seasonal-leaves/smoke.py --runtime /path/to/installed-forge
```

`smoke.py` запускає окремий тимчасовий світ чотири рази: зиму й весну після перезапуску, потім повторює цикл з увімкненим persistent-листям. Перевіряє межу чанків, сторонній тип листя через тег, повернення властивостей, захист будівель, вирубаних дерев, декоративного, водонаповненого й непідтримуваного листя. Тестовий мод не встановлювати на робочий сервер.

## Оновлення 1.1.0: трава й дикі рослини

Замість старого `empirecraft-seasonal-leaves-1.0.0.jar` установіть **тільки** `empirecraft-seasonal-leaves-1.1.0.jar` та оновлений конфіг. Старі резервні записи листя читаються без міграції. Новий архів — `dist/Empirecraft-Seasonal-Leaves-1.1.0.zip`; клієнтам новий мод не потрібний. Після встановлення потрібен повний перезапуск сервера.

Наземна трава, папороті, квіти й модові наземні рослини зникають і повертаються у свої сезони. На початку дозволеного сезону поява плавна, в останньому підсезоні перед періодом спокою рослини поступово зникають. Звичайна трава зелена навесні–восени й відсутня взимку; конопля — навесні/влітку, обидві дикі кави — влітку/восени. Інші явні види використовують перевірені сезони поточного календаря зі `vegetation-profiles.json`. Для інших звичайних наземних рослин беруться сезонні теги Serene Seasons, а за їх відсутності — весна/літо/осінь.

Автоматичне розпізнавання охоплює наземні `BushBlock`, зокрема модові квіти й папороті; культурні `CropBlock`, саджанці, азалії, горщики та листя з автоматичного списку виключені. Явно налаштовані дикі види підтримуються окремо. Додаткові блоки можна включити тегом `empirecraft_seasonal_leaves:additional_vegetation`, а винятки — `empirecraft_seasonal_leaves:evergreen_vegetation`. Водні/водонаповнені рослини, block entity й нестандартні конструкції не перетворюються на сухопутні аналоги. Нативні двоблокові рослини прибираються й повертаються обома половинами.

Уже наявні сезонні рослини утворюють збережений у чанку банк насіння: початкові blockstate, вік та обидві половини повертаються, якщо місце й природний ґрунт залишилися придатними. Немає предметного дропу від сезонного зникнення. Поставлені на їхньому місці блоки не перезаписуються, видобуті живі рослини не відновлюються зі старого запису. Нова природна поява трави та місцевих квітів можлива окремо.

Для нової трави — не більш як 48 зайнятих рослинами колонок на чанк, не більш як одна посадка за завершений прохід. Модові квіти поширюються з видів, уже спостережених у цьому чанку: доповнення не розносить усі екзотичні квіти по кожному біому. Наявна система World Rules продовжує появу своїх 33 диких рослин із власними перевірками клімату, місця та Towny. Нова інтеграція фільтрує її кандидатів за сезоном і рідкістю; попередня календарна перевірка залишається чинною.

### Рідкі конопля й кава

Спільна група: `nirvana:wild_hemp`, `farmersrespite:wild_coffee_bush`, `rusticdelight:wild_coffee`.

- Приблизно **один придатний чанк зі 128**, детерміновано за seed світу та координатами. Це не гарантія рослини в кожному такому чанку: потрібні ще правильний біом, сезон і вільне місце.
- **Не більш як одна жива рослина всієї групи на чанк** під час нового природного відновлення/сезонного повернення.
- **Сім ігрових днів** до нової появи після останнього спостереження рослини. Тривалість дня береться з Serene Seasons; перезапуск її не скидає.
- Нові правила не зрізають наявні поклади масово посеред дозволеного сезону. Після природного сезонного зникнення повернення вже підкоряється рідкісному ареалу й ліміту. Неповернуті записи залишаються в банку насіння; вимкнення доповнення дозволяє їх відновити.

### Привати, ферми та налаштування

Розділ `[vegetation]` у тому самому конфігу. `requireWilderness=true` повторно використовує перевірку `TownyWilderness` з установленого World Rules. Немає Towny/World Rules, плагін ще не готовий або стан привату невідомий — зміни рослин зупиняються. Нові рослини не садяться в приватах. Банк насіння також чекає, доки місце знову дозволить зміну.

Грядки не обробляються: придатний лише природний субстрат, не farmland. Рослини, які гравці посадили після встановлення 1.1.0, запам'ятовуються й пропускаються. Старий декоративний кущ на природному ґрунті за станом блока неможливо відрізнити від дикого; його захищають Towny та тег винятків. Рослини під закритим дахом не прибираються. Тропічні біоми не переводяться на помірну зиму, але рідкість коноплі й кави залишається чинною.

Параметри: `enabled`, `requireWilderness`, `regrowGroundCover`, `positionsPerLevelTick`, `plantsPerLevelTick`, `rescanDelayTicks`, `maxGroundCoverPerChunk`, `rareHabitatOneInChunks`, `rareCooldownDays`. Рекомендований серверний конфіг уже містить ці значення. Нові резервні дані зберігаються разом із блоками у NBT чанка `empirecraft_seasonal_vegetation_v1`.

Додаткові перевірки:

```sh
python seasonal-leaves/mixin_test.py --world-rules server/mods/empirecraft-world-rules-1.0.2.jar --calendar server/mods/empirecraft-calendar-1.1.1.jar
python seasonal-leaves/smoke.py --runtime /path/to/installed-forge --vegetation-only
```
