# Empirecraft Seasonal Leaves 1.3.1

Forge-мод для Minecraft 1.20.1: виразна сезонна погода, різнокольорова осіння крона та листя, яке зберігає опору під гравцем. Потрібні Serene Seasons **9.1.0.3** і GlitchCore **0.0.1.1**. **Однаковий JAR тепер установлюється на сервер і клієнти.** Збережено механіки рослин, повільного відновлення й `/plantgrowth` із 1.2.2.

## Що змінилося

- Узимку автоматичні періоди опадів тривають **2–5 налаштованих днів Serene Seasons**. За `day_duration=57600` це 115200–288000 серверних тіків. Між ними є сухі перерви; влітку дощі коротші, а сухі періоди довші, навесні та восени опадів більше.
- Сніг використовує клімат Serene Seasons. У холодних і помірних біомах узимку це сніг; доповнення не перетворює бездощову пустелю на сніговий біом. Виміри беруться з білого списку Serene Seasons.
- Зимове небо та туман блідіші й сіріші, восени є слабше приглушення кольорів. Збережено нічну яскравість, переходи штатної погоди та кольори підводного туману.
- Осінні кольори визначає **код**, без нових ігрових текстур: жовтий, золотавий, помаранчевий, рудо-коричневий і темно-коричневий. Вид блока, координати та невеликі просторові групи дають різні відтінки на одному дереві. Перехід поступовий; вибір відтінку та часу початку сталий, без мерехтіння після перезаходу.
- Нове весняне листя зберігає початкове зелене тонування Serene Seasons. Колір не задає порядок опадання. Жовте листя може опасти, поки помаранчеве або коричневе ще лишається. Попереднє поступове опадання й весняне відновлення крони збережені.
- Автоматичне опадання та звичайне згнивання листя тимчасово пропускають опору під гравцем під час стояння та стрибка. Після відходу є приблизно 3 секунди запасу, потім сезонне опадання продовжується. Листя все ще можна зламати інструментом; вибухи та рубання дерев не блокуються.

## Листя та клієнтський рендер

Обробляються блоки з `minecraft:leaves` або `empirecraft_seasonal_leaves:additional_leaves`, незалежно від namespace. Збережено наявні datapack-винятки серверного опадання. Моделі без tint index також отримують можливість сезонного тонування; початкові текстури, UV, геометрія, прозорість і освітлення збережені. Тонування множиться на пікселі оригінальної текстури: вже кольорові текстури можуть відрізнятися від сірих стандартних текстур листя.

Підтримані стандартний Forge-рендер і **Embeddium 0.3.31**. Embeddium обходить звичайний `BlockColors`, тому для нього є окрема необов'язкова інтеграція. Відсутність Embeddium перевірена окремо. Шейдерні пакети можуть замінювати власним кодом колір неба/туману; графічний тест із конкретними шейдерами не проводився. Нестандартні дерева без блоків/тегів листя потребують окремої інтеграції або додаткового тега.

## Оновлення

1. Зупиніть сервер і всі клієнти. Збережіть резервну копію світу та старого конфігу.
2. На сервері приберіть старий `empirecraft-seasonal-leaves-*.jar` і встановіть **один** `empirecraft-seasonal-leaves-1.3.1.jar` у `mods/`. Попередній конфіг і дані крон/рослин залиште.
3. Поставте той самий JAR у `mods/` кожного клієнта. Serene Seasons/GlitchCore мають бути на обох сторонах; окремий ресурс-пак не потрібний.
4. Якщо працює ADM, додайте запис `empirecraft_seasonal_leaves` версії `1.3.1` із контрольною сумою JAR. Повний ADM-файл у пакеті призначений для складу модів цієї гілки. Для власного складу оновіть лише цей запис звичайним механізмом ADM.
5. Повністю перезапустіть гру й сервер. `/reload` не встановлює JAR. Нові поля конфігу додадуться автоматично; вибір `/plantgrowth off` збережеться.

Готові файли: [JAR](dist/1.3.1/empirecraft-seasonal-leaves-1.3.1.jar), [пакет установлення](dist/1.3.1/Empirecraft-Seasonal-Leaves-1.3.1-install.zip), [вихідний код](dist/1.3.1/empirecraft-seasonal-leaves-1.3.1-source.zip). ZIP треба розпакувати, а не перейменовувати на JAR.

## Налаштування та команди

Новий розділ того самого `config/empirecraft_seasonal_leaves-common.toml`:

```toml
[atmosphere]
seasonalWeather = true
protectPlayersOnLeaves = true
autumnColors = true
seasonalSky = true
```

Перші два параметри працюють на сервері; кольори й небо — на клієнті. Наявні `enabled`, `includePersistentLeaves`, `[vegetation]` та `growthEnabled` зберігають попереднє значення й призначення.

| Команда адміністратора, рівень прав 2 | Дія |
| --- | --- |
| `/plantgrowth on`, `/plantgrowth off`, `/plantgrowth status` | Попереднє керування ростом і відновленням |
| `/seasonweather status` | Поточна погода, режим і залишок періоду в днях календаря |
| `/seasonweather auto` | Завершити ручний погодний override й повернути сезонний розклад із поточного стану опадів |

`/weather clear` та інші ручні зміни таймера поважаються. `doWeatherCycle=false` зупиняє автоматичний контроль. Перезапуск не подовжує активний шторм: його часовий кінець зберігається разом із серверним світом. Відлік погоди використовує серверні тіки; вимкнений сервер не виконує погодні тіки.

## Як перевірити у грі

- Осінь: `/season set mid_autumn`, огляньте дуб, березу й модові дерева на рівному майданчику. Сусідні листки мають відрізнятися; колір поступово оновлюється. Перезайдіть: та сама позиція в ту саму пору має той самий відтінок.
- Зима: `/season set mid_winter`, потім `/weather rain` і `/seasonweather auto`. Через секунду `/seasonweather status` має показати близько 2–5 днів опадів. У помірному біомі перевірте сніг, бліде небо й туман; уночі небо має залишатися темним.
- Листя: під час зимового опадання постійте й пострибайте по кроні. Опора має залишитися. Відійдіть: після запасу часу й чергового проходу сезонне опадання продовжиться.
- Ручна погода: `/weather clear 1000`, перевірте суху погоду; `/gamerule doWeatherCycle false` має залишити погоду під ручним керуванням. Повернення: `true` і `/seasonweather auto`.
- Перезапустіть сервер під час довгого шторму: залишок має зберегтися, без нового випадкового подовження. Перевірте `/plantgrowth status` і попередній стан росту.

Сезонні команди змінюють календар світу; для перевірок використовуйте копію світу або поверніть потрібний сезон після тесту.

## Навантаження

Погодний контроль — раз на 20 тіків, зміни таймерів лише на переходах; опади передаються штатними пакетами Minecraft. Захист опори кешує невеликі області під гравцями раз на 10 тіків, при стрибку та одразу при переході опорної області на сусідній блок. Для нерухомого гравця немає додаткового пошуку щотік; для кожного листка не перебираються всі сутності. Сусідні чанки не завантажуються примусово.

Кольори рахуються під час побудови клієнтських мешів. Зміна сезону оновлює лише відомі секції з листям, до 8 секцій за клієнтський тік; немає одноразового скидання всього рендера. Кеш секцій обмежений 8192 записами, кеш додатково тонованих списків — 128 на модель; ресурсне перезавантаження очищає кеш моделей. Параметри сканування листя й рослин лишилися попередніми.

## Збирання та перевірки

Потрібні JDK 17 і бібліотеки Mohist/Forge 1.20.1 47.4.23. Офлайн-процес використовує справжні встановлені класи й явну таблицю клієнтських API з `tools/client-api.srg`; API-заглушки не пакуються та не використовуються для main compilation. Вхідні моди закріплені SHA-256 у `build-inputs.json`, `client-inputs.json`, `compat-inputs.json`.

```sh
python3 build.py --server-home /path/to/server --embeddium /path/to/embeddium-0.3.31+mc1.20.1.jar
python3 test.py
python3 mixin_test.py --server-home /path/to/server --embeddium /path/to/embeddium-0.3.31+mc1.20.1.jar
python3 build.py --server-home /path/to/server --prepare-effects-fixture
python3 growth_smoke.py --server-home /path/to/server --effects --java /path/to/java21
python3 build.py --server-home /path/to/server --prepare-fixture
python3 growth_smoke.py --server-home /path/to/server --java /path/to/java21
python3 package.py
```

Для звичайного Gradle-проєкту додайте оригінальні залежності до `libs/` згідно з його README й виконайте `./gradlew build`. Gradle-збирання в цьому середовищі не запускалося; готовий JAR зібрано наведеним офлайн-процесом.

Перевірено 100 000 погодних тривалостей, неоднорідність крон, незалежність кольору від опадання, темні зимові ночі, справжні серверні/клієнтські Mixin-перетворення, роботу з Embeddium і без нього, а також виконання виробничого helper на справжньому Forge `BakedQuad`. Чотири запуски тимчасового Mohist перевірили опору під час Forge jump event, звичайне згнивання, довгий шторм, ручну погоду, gamerule, збереження після перезапуску та старий `/plantgrowth`.

Повний графічний клієнт із вашим світом/ресурс-паками та вимірювання FPS/TPS великих навантажень не запускалися. Детальні результати й контрольні суми — `dist/1.3.1/validation.json`.
