# OELib: виправлення одночасної реєстрації пакетів

У наданому логу попереднє виправлення ChatPlus уже працює. Наступний збій —
`ConcurrentModificationException` в OELib 0.2.4.1 під час створення знімка
списку пакетів, коли Contact паралельно додає свій пакет.

`Collections.synchronizedSet` захищає окремі операції, але ітерація в
`Set.copyOf` відбувалася без блокування. Перелік базових пакетів тепер
використовує `CopyOnWriteArraySet`: його ітератори читають стабільний знімок.
Зберігаються порядок додавання, відсутність дублікатів та наявна логіка
сканування й пізньої реєстрації. Змінено лише ініціалізацію цього набору.

`RaceTest.java` примусово додає елемент між отриманням ітератора й копіюванням,
відтворює старий збій та перевіряє виправлений клас, порядок і дублікати.
Тестовий доступ через Unsafe використовується лише у перевірці; у мод він
не потрапляє. Додатково перевіряється справжня доставка Contact після запуску
й перезапуску тимчасового сервера.

## Встановлення

Закрийте клієнт і зупиніть сервер. Із `Empirecraft-OELib-Startup-Fix.zip`
скопіюйте `client/` у клієнтську збірку, а `server/` — у серверну, замінивши
JAR і список ADM. Пакет містить також актуальні Bridge та Towny Recruits
із попередніми виправленнями запуску. Залиште по одній копії кожного мода.

## Відтворення

Оригінальний JAR зафіксований у `native-inputs/`. Потрібні JDK 17 і Python 3:

```sh
python3 oelib-fix/build.py
python3 oelib-fix/test.py
```

Виправлений клас також закріплений у `native-content/retained-code.json`;
загальна перебудова збірки зберігає його. Мережеві повідомлення та їхні
формати не змінені. Відомості про автора Flechazo і ліцензію MIT з оригінального
`META-INF/mods.toml` збережені. Цей каталог містить лише джерела виправлення,
а не переписану бібліотеку. Повний графічний клієнт не запускався.
